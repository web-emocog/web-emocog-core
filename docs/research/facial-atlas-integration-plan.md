## Граница первого этапа

1. Диагностическая карта 18 зон и справочник каналов; не изображение активности
   мышцы или нерва. Стороны относительно участника, а не зеркального preview.
2. Адаптер уже вычисленных кадров общего pipeline. Никаких дополнительных
   camera/inference loops или автоматического включения в опубликованные сессии.
3. Раздельные `absolute`, `baseline`, `delta`, MAD, пригодность и причины
   пропуска для каждого канала. Никаких новых классификаторов эмоций,
   эпизодов, симметрии или суммарной активности области.
4. Примерная настройка прототипа 5 с / 25 отсчётов не становится автоматически
   порогом приёмки продукта. DOCX также указывает ожидаемую частоту 20 Гц и
   максимальный разрыв 300 мс; эти параметры необходимо согласовать с реальным
   расписанием канала, а не с паспортными FPS камеры.
5. Готовность одного канала, достаточная для диагностического прототипа,
   не разрешает считать готовыми все обязательные каналы исследования.

## Производственные данные и аналитика

До штатной записи нужен отдельный версионированный закрытый контракт. Не
добавлять произвольные поля в `emotion_summary` или разрешающий
`additionalProperties`. Согласовать объём записи до включения: диагностический
лимит 1200 кадров / 24 МиБ не является готовой политикой длинной сессии.

Необходимые измерения и происхождение:

- method/catalog/extractor/model versions и сохранённые настройки;
- подтверждённая ориентация входа, неизменяемая база и её собственный интервал;
- исходное время кадра в существующей монотонной шкале;
- session/block/trial/presentation/attempt identity из контекста захвата;
- число реально пригодных измерений, знаменатель покрытия, максимальный разрыв;
- неизвестные каналы/база/качество как null с причиной, не ноль;
- только производные данные, без изображения и полной сетки лица.

Для UI нужны интервалы сессии, блока, конкретного предъявления и выделенного
участка; отметки событий, таблица каналов, небольшие графики, выбор по зоне
и экспорт тех же выбранных рядов. Не соединять длинные разрывы линией.
Не создавать престимульный baseline, если протокол его не содержит. При
группировке сохранять участников и попытки, не считать соседние кадры
независимыми участниками.

## Порядок реализации и приёмка

| Шаг | Условие готовности |
| --- | --- |
| Согласование | Перечень обязательных каналов, стороны/ориентация, правила базы, частота и допустимые пропуски подтверждены владельцем методики |
| Диагностика | Адаптированный каталог/карта и bounded локальный экспорт; тест одностороннего движения, null, очков/закрытого лица, teardown |
| Контракт | Schema + types + producer + validator + bounded retention + отрицательные security tests одним изменением |
| Аналитика | Выбор зоны/канала/интервала, повторные попытки не склеиваются, ряды и таблицы соответствуют экспорту |
| Независимая проверка | Повторяемость, помехи позы/речи/освещения и эталонная AU-разметка; никаких диагностических обещаний |

Приложенный patch ориентирован на `1c1e571`. Проверка без применения на
обновлённой рабочей ветке выявила несовместимые диагностические entrypoints.
Нельзя применять его с force, заменять новые pipeline-файлы старой копией или
выдавать 30 прошедших тестов автономного пакета за готовую интеграцию.

Правила сочетаний имеют внешние пороги. До согласования порогов результат
неопределён; их нельзя выводить из этой спецификации самостоятельно.
