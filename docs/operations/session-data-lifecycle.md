# Данные сессии: согласие, доступ и удаление

Статус: инструкция для локальной приёмки, не утверждённая политика хранения
и не основание запускать сбор у внешних участников.

| Контур | Что хранится | Что проверено |
| --- | --- | --- |
| Протокол на сайте | В браузере: временные наблюдения, черновик сессии, очередь отправки. В API: ограниченный пакет признаков, проб, событий, QC и версия публикации. Сырые кадры, аудио и видео не входят в API-пакет. | PostgreSQL и браузерные тесты. Незавершённый результат не равен завершённому. |
| Опрос | Только ответы на вопросы закреплённой публикации. Свободный текст допустим для объявленного открытого вопроса; проверка запрещённых значений не заменяет ручное обезличивание. | Необъявленные поля, варианты, дубли и ряд идентифицирующих значений отвергаются. Не запрашивайте персональные сведения в тексте ответа. |
| Аналитика и выгрузки | Снимок выборки содержит ссылки на сессии и фильтры; новый экспорт формируется на запрос. Удалённая запись исчезает из будущих выгрузок. Скачанный файл контролирует его получатель. | Проверены запреты межпроектного чтения и экспорта, а также отозванное членство. Псевдоним не равен анонимизации. |
| Observer и Dota | Отдельные пилоты с другой поверхностью разрешений и возможными локальными файлами. | Не входят в серверный маршрут удаления сессий и не допущены этим отчётом к сбору. Для каждого нужны собственная карта файлов, согласие и проверка удаления. |

При выдаче ключа отправки браузер передаёт версии документов. API записывает
их и своё время получения. Запись о согласии не содержит подписи,
не подставляется для исторических сессий и не доказывает, что участник
прочитал текст. Документ нельзя исправлять под тем же номером: новая
редакция требует новой версии, синхронного обновления ссылок и проверки API.

## Проверка на синтетической сессии

1. В отдельном проекте пройдите согласие и создайте тестовую сессию. Проверьте
   сохранение, версию публикации, наличие записи о согласии и доступ в аналитике.
   По запросу на реальное удаление сначала проверьте полномочия и принадлежность
   сессии; не используйте почту или полное содержимое результата как открытый идентификатор.
2. Сохраните тестовый снимок выборки. Из разрешённого кабинета выполните
   `DELETE /sessions/:id`, где `:id` — числовой ключ в БД, не публичный ID.
   Для cookie-сессии нужен актуальный CSRF. Право на удаление уже, чем на просмотр.
3. Подтвердите отсутствие сессии, зависимых результатов, событий, записи о
   согласии и затронутого снимка. Проверьте, что прежний участнический ключ
   не может создать эту сессию повторно. Сервер хранит только хеш ID и дату удаления.
4. При `503 session_erasure_unconfirmed` сначала проверьте текущее состояние;
   сообщение об ошибке не доказывает, что транзакция откатилась.
5. Скачанные JSON/CSV/PDF и браузерные копии удаляются отдельно на тех
   устройствах, где они были сохранены. Запрос API их не стирает.

## Перед запуском с внешними участниками

- Утвердить владельца обработки, проверяемый контакт, сроки для основной БД,
  логов, копий и выгрузок. Адрес `privacy@emocog.com` и сроки в версии 1.0
  не подтверждены этой технической проверкой. Не объявлять их действующей
  операционной политикой без проверки и обновления документов.
- Не открывать восстановленный старый снимок для пользователей, пока в
  изолированной среде не перенесены более свежие записи об удалении и не
  удалены восстановленные сессии и зависимые снимки. Сам триггер блокирует
  новую запись, но не стирает то, что уже лежало в восстановленной копии.
- Проверить процедуру на реальной резервной копии: удалённая сессия после
  восстановления не читается и не принимается повторно; остальные сессии
  и файлы доступны владельцам. Автоматическое истечение копий и процедуру
  переноса журнала удалений в рамках этого прогона не проверяли.
