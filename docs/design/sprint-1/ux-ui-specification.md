# UX/UI specification летнего релиза

Статус: `Draft for team review`

Ответственный: Валерия

Период: 21.07-03.08.2026

## 1. Цель

Сформировать один источник истины для движения исследователя и участника, визуальных правил, системных состояний и передачи макетов во frontend. Спецификация не меняет production UI в Sprint 1.

## 2. Принципы интерфейса

1. Пользователь всегда понимает, где находится, что уже сделано и какое действие является следующим.
2. Один экран содержит одно главное действие. Вторичные действия визуально тише.
3. Навигация кабинета доступна из любого researcher-экрана. Вкладки проекта не заменяют глобальную навигацию.
4. Публикация протокола отделена от сохранения черновика и требует предпросмотра.
5. Качество сигнала и данных не маскируется. `No data`, `low confidence`, `off-screen`, `mock` и техническая ошибка имеют разные состояния.
6. Метрики описывают наблюдаемые сигналы, а не медицинские или диагностические выводы.
7. Ошибка объясняет, что произошло, что сохранено и что пользователь может сделать дальше.

## 3. Информационная архитектура

### Кабинет исследователя

Основной путь:

```text
Вход -> Главная -> Проекты -> Проект -> Протокол -> Конструктор
     -> Предпросмотр -> Публикация -> Участники -> Мониторинг
     -> Сессия -> Результаты -> Экспорт
```

Библиотека стимулов и шаблонов доступна глобально и может открываться из конструктора без потери черновика.

### Веб участника

Основной путь:

```text
Приглашение -> Согласие -> Проверка устройства -> Калибровка
-> Инструкция блока -> Задание + SAM -> Завершение
```

Краевые состояния возвращают пользователя только на безопасный предыдущий шаг. Повторная загрузка не должна начинать новую сессию без явного подтверждения.

### Breakpoints

| Режим | Диапазон | Поведение |
| --- | --- | --- |
| Desktop | `>= 1200px` | sidebar + content, таблицы без горизонтального скролла |
| Tablet | `900-1199px` | компактный sidebar, двухколоночные блоки могут стать одной колонкой |
| Mobile | `< 900px` | drawer navigation, sticky primary action, cards вместо широких таблиц |

На ширине `390px` обязательны: доступ к навигации, читаемая форма без zoom, отсутствие горизонтального scroll всей страницы и touch targets не меньше 44px.

## 6. Компоненты и состояния

### Button

Варианты: `primary`, `secondary`, `quiet`, `danger`.

Состояния: default, hover, active, focus-visible, disabled, loading.

Primary используется не более одного раза в видимой зоне. Loading сохраняет ширину кнопки и блокирует повторный submit.

### Field

Состояния: empty, filled, focus, error, disabled, readonly.

Ошибка располагается под полем, связана через `aria-describedby` и не исчезает до исправления значения.

### Status badge

Варианты: draft, collecting, complete, valid, borderline, invalid, interrupted, no-data.

`qc_score` всегда сопровождается шкалой и пояснением. Значение `0` не используется вместо отсутствующих данных.

### Data panel

Обязательные метаданные: источник, период, sample count, QC/confidence и версия алгоритма, когда она влияет на интерпретацию.

### Notification

Варианты: neutral, success, warning, error.

Error содержит действие восстановления. Для фоновой ошибки допускается inline alert; modal используется только при потере данных или необратимом действии.

## 7. Системные состояния

| Состояние | Что показываем | Чего не делаем |
| --- | --- | --- |
| Loading | skeleton структуры и понятный label | не показываем случайные значения |
| Empty | причина отсутствия данных и следующий шаг | не отображаем пустой график как нулевой |
| Error | краткая причина, сохранность данных, retry/contact | не используем только код ошибки |
| Permission denied | требуемое право и владелец доступа | не показываем недоступные данные под overlay |
| No data | `Нет данных за выбранный период` | не подставляем demo |
| Mock | заметный badge `Демонстрационные данные` | не смешиваем с production |
| Low confidence | значение, причина и фильтр исключения | не выдаём как надёжный результат |
| Off-screen | `Взгляд не определён на странице` | не clamp-точку к ближайшей цели |
| Degraded signal | продолжаем только допустимый сценарий | не скрываем ухудшение |
| Upload pending | локально сохранено, повтор отправки | не объявляем сессию загруженной |

## 8. QC, confidence и формулировки

Допустимо:

- `Качество записи: пограничное`.
- `Взгляд определён для 72% валидных кадров`.
- `Недостаточно данных для вывода`.
- `Модель зафиксировала наблюдаемый паттерн`.

Недопустимо:

- `У пользователя деменция`.
- `Участник невнимателен`.
- `Эмоция точно определена`.
- `Взгляд был на цели`, если confidence/OOD gate не пройден.

На страницах результатов отображается постоянное пояснение: результаты предназначены для исследовательской интерпретации и не являются медицинским заключением.

## 9. Доступность

- Contrast текста и интерактивных элементов не ниже WCAG 2.2 AA.
- Все действия доступны с клавиатуры.
- `focus-visible` не удаляется и имеет контрастное кольцо не менее 2px.
- У страницы один `h1`, заголовки не пропускают уровни.
- Таблицы имеют caption или видимый заголовок, `th` и мобильное карточное представление.
- Графики имеют текстовую сводку и доступную таблицу данных.
- Ошибки формы объявляются через `aria-live`.
- Анимация отключается через `prefers-reduced-motion`.
- Статусы не различаются только цветом.

## 10. Логика переходов

1. Создание проекта завершается обзором проекта, а не пустой главной.
2. Создание протокола открывает конструктор с сохранённым project context.
3. Выход из конструктора при несохранённых изменениях требует подтверждения.
4. Публикация доступна после валидации, предпросмотра и подтверждения version freeze.
5. Ссылка участника копируется из раздела `Участники`.
6. Клик по сессии из мониторинга или результатов открывает одну и ту же карточку с сохранёнными фильтрами возврата.
7. Экспорт повторяет активную выборку и отображает её параметры до скачивания.

## 11. Границы Sprint 1

В Sprint 1 разрешены изменения только в design/docs/Figma. Production CSS/HTML и JS не изменяются. Реализация макетов начинается после фиксации функциональных сценариев AOI, analytics и participant lifecycle.
