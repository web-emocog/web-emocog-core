# Выгрузка для независимого пересчёта

В карточке сессии под «Ограничения отчёта» доступна кнопка выгрузки плана,
попыток и интервалов. Это сохранённые данные всей выбранной сессии, не
снимок текущих фильтров экрана. Для обычного отчёта с фильтрами используйте
экспорт снимка выборки.

API: `GET /export/reproducibility?project_id=…&protocol_id=…&session_db_id=…&format=json`.
`session_db_id` является числовым идентификатором из карточки; вместо него
можно задать строковый `session_id`. Допустимы `protocol_version` в формате
`publication:N`, `invitation:N` или `legacy`, `date_from`/`date_to` (ISO),
`format=json|csv`. Без идентификатора сессии выгружается выбранная группа
сессий проекта по этим параметрам, а не пользовательские группы снимка.

Сервер повторно проверяет роль, организацию, членство в проекте и наличие
сессий перед выдачей. На запрос: не более 50 сессий, 8 МиБ исходных данных,
25 000 строк и 16 МиБ результата, не более двух параллельных выгрузок на
процесс. Превышение возвращает 413; сузьте отбор по датам или публикации.
Усечённый успешный ответ не выдаётся. Сервер не хранит готовый файл.

## Словарь

| Поля | Смысл |
| --- | --- |
| `session_id`, `participant_id`, `project_id`, `protocol_id`, `protocol_version` | Сессия, псевдоним участника внутри проекта, проект и закреплённая версия. Псевдоним не делает данные анонимными. |
| `group_id`, `condition_id` | Только сохранённое назначение; `null` означает, что оно не зафиксировано. Группы, заданные вручную в отчёте, здесь не реконструируются. |
| `block_id`, `trial_id`, `presentation_id`, `attempt`, `attempt_status` | Блок, запланированная проба, отдельный показ и попытка. `accepted`, `excluded`, `incomplete`, `unknown` не взаимозаменяемы. |
| `clock`, `time_origin_ms`, `onset_perf_ms`, `onset_epoch_ms` | Порядок и часы. `perf` относится к конкретному запуску страницы, `epoch` зависит от системных часов. Ни одно не означает аппаратный замер. |
| `interval_start_ms`, `interval_end_ms`, `observed_ms`, `coverage_fraction` | Границы, наблюдаемое время и покрытие. Интервалы минут и блоков перекрываются; их нельзя складывать. В RT-окнах доля относится к отсчётам, а не к длительности. |
| `value`, `unit`, `method_version`, `sample_count` | Значение, единица, метод и количество наблюдений. `null` не равно нулю; `sample_count` не равно числу независимых участников. |
| `recording_integrity`, `signal_quality`, `suitability`, `quality_valid`, `missing_reason`, `reason_codes` | Полнота, наличие наблюдения, границы интерпретации, качество попытки и причины пропуска. Успешное сохранение не даёт научной валидации. |
| `presentationPlan`, `seed`, `rngVersion`, `sourceInputs`, `blocks`, `actual` | План для проб конструктора, выполняемых общим циклом предъявления: алгоритм жеребьёвки, входы, расписание и фактические показы. Отдельные модули VPC/визуальных тестов этим форматом не покрыты. `counterbalancing.mode=none` означает, что распределение между участниками не задано. |

CSV в первой строке данных содержит `source_kind=manifest`, где сохранены
метаданные и план. JSON удобнее для вложенного плана. Файл не содержит
сырое видео, звук, произвольные ответы и коды приглашений. Сохранённые
окна связности экспортируются; пропущенные из-за лимита 200 попыток окна
из RT-строк восстановить нельзя. Аналогично с лимитами физиологии и картами
взгляда. Набор предназначен для пересчёта RT/физиологии в указанном объёме,
не для реконструкции сырых измерений или полной репликации AOI/heatmap.
План отмечает обрывы до показа, обрезку окна таймером и пропуски медиа.
Плановое окно, время регистрации браузером и физический показ не тождественны.

`datasetSha256` — SHA-256 сериализации `JSON.stringify` полного JSON-пакета
без самого поля `datasetSha256`, с сохранением порядка полей. Параметры
выборки `selection` включены в эту сумму до сериализации ответа и проверки
лимита размера. В CSV сохранена та же сумма в строке `manifest`; это сумма
типизированного JSON-набора, не байтов CSV-файла и не цифровая подпись сервера.

Для физиологических интервалов `method_version` относится к конкретному каналу
и интервалу, не к версии JSON-структуры. Старые интервалы без сохранённого метода
помечены `legacy_summary`, смесь — `mixed_methods`; метод новых блоков не
подставляется старым. Сохранённое `condition_id` также передаётся в строки
RT-окон. Для старой сессии без lifecycle `recording.completed` равно `null`
с причиной `recording_status_not_recorded`, а не подтверждённому `false`.

```bash
python3 scripts/research/recalculate_export.py wecog-reproducibility.json
python3 scripts/research/recalculate_export.py wecog-reproducibility.csv
```

Пример независимо пересчитывает медиану правильных принятых RT внутри
участника, затем медиану с равным весом участников, а также поминутное
покрытие физиологии. В контрольном наборе участники A и B дают медианы
200 и 400 мс, группа даёт 300 мс. Повторные сессии участника A не увеличивают
его вес, исключённая попытка 999 мс и отсутствующий ответ не входят в итог.
