# Session Runtime и API-контракты v1

## Дополнение: уникальная выборка проверки взгляда

Опциональные `gazeValidation.samplingVersion: unique_capture.v1`, `sampling`
(не более 14 сводок, по 60 опросов максимум) и `coverage: target_coverage.v1`
описаны в SessionFeature JSON Schema и TypeScript. В ingest идут только счётчики
по точкам и полнота benchmark, не сырые gaze samples или capture timestamps.
Client compaction явно сохраняет allowlisted сводки sampling; остальная raw
validation-серия по-прежнему исключается. Server policy проверяет типы, лимиты,
уникальность stage/index, сумму счётчиков, согласованность clock/accepted и
coverage, наличие принятых benchmark samples для каждой заявленной наблюдавшейся
точки. Текущая версия требует ровно пять benchmark-целей. `passed: true` с неполным coverage отклоняется до записи; существующий
checkpoint не заменяется. Legacy summaries без новых полей совместимы; миграций
БД нет. Методика и ограничения: [gaze methods](../research/gaze-blink-body-methods.md).

## Назначение

`apps/participant-web/js/session-runtime/` управляет единой измерительной
сессией участника. После precheck и до начала калибровки запускается один
видеопайплайн, который непрерывно обслуживает gaze, blinks/PERCLOS, emotions,
body pose/movement, QC и BPM. Опциональный аудиопайплайн запускается только
после отдельного согласия участника и не блокирует видеопайплайн при отказе в
доступе к микрофону. Без калибровки координаты gaze не считаются
достоверными и не публикуются, остальные сигналы продолжают собираться. RT
фиксируется глобальными обработчиками ввода только внутри активного испытания.

Сырые видео и аудио не сохраняются и не отправляются на API. В итоговый `SessionFeature` входят
агрегаты, типизированные события, состояние lifecycle и признаки качества.
Emotion и body pose используют online accumulators всей сессии; ограничение
размера диагностического массива не меняет итоговые средние.

## State machine

| Состояние | Назначение |
| --- | --- |
| `idle` | runtime ещё не запущен |
| `starting` | инициализация сессии |
| `instruction` | экран инструкции, пауза разрешена |
| `running` | выполняется испытание, пауза запрещена |
| `paused` | ручная пауза на инструкции |
| `quality_error` | длительное ухудшение условий измерения |
| `technical_error` | ошибка сети, камеры или модуля |
| `finishing` | остановка модулей и подготовка результата |
| `completed` | локальная сессия завершена |
| `failed` | невосстановимая ошибка завершения |

Пауза начинается и заканчивается только действием участника. Ошибка во время
испытания не ставит таймер задания на скрытую паузу: текущая попытка помечается
невалидной, сохраняется для аудита и после инструкции повторяется с новым
номером `attempt`.

## Контроль качества

Ошибки качества:

- лицо отсутствует не менее 1.5 секунды;
- плохое освещение сохраняется не менее 2.5 секунды;
- мешающая поза или нестабильность головы сохраняется не менее 2.5 секунды;
- подтверждённое FaceSegmenter перекрытие лица рукой длится не менее 2 секунд.

Live detector, итоговый QC и inline fallback используют региональные признаки
`*_hand_occluded`, а не глобальный `handDetected`/`hand_on_face`. Глобальная
skin/hand mask сама по себе не доказывает перекрытие лица. Новые summaries
помечены `faceVisibilityMethod=regional_hand_evidence.v2`. `faceVisible`
означает обнаружение лица; `faceOk` дополнительно учитывает его размер,
положение и перекрытие. Старые summaries не пересчитываются автоматически.

Краткие движения головы, короткие изменения света и
`low_skin_visibility` не бракуют блок. Ошибки MediaPipe/анализа после трёх
последовательных кадров, остановка camera track, отказ BPM и потеря сети
классифицируются как технические.

Перед испытаниями UI показывает условия проведения: нельзя проходить тест в
движущемся транспорте, в темноте, с сильной засветкой сзади, лёжа или с
закрытым лицом. Естественные краткие движения головы и небольшие изменения
света допустимы.

## Контракты

Канонические схемы:

- `packages/shared/contracts/session-feature.v1.schema.json`;
- `packages/shared/contracts/session-event.v1.schema.json`;
- `packages/shared/contracts/session-lifecycle.v1.schema.json`;
- `packages/shared/contracts/ingest-session-feature-response.v1.schema.json`;
- TypeScript-типы: `packages/shared/contracts/session-contracts.d.ts`.

API публикует схемы:

```text
GET /contracts
GET /contracts/session_feature.v1
GET /contracts/session_event.v1
GET /contracts/session_lifecycle.v1
GET /contracts/ingest_session_feature_response.v1
```

Алиасы с именами файлов, например
`/contracts/session-event.v1.schema.json`, также поддерживаются для JSON
Schema resolver и обратной совместимости.

Все записи `SessionFeature.events` имеют `schemaVersion=session_event.v1`,
`eventId`, категорию, severity, абсолютное и относительное время, фазу,
`blockId` и `trialId`. Старые дополнительные поля событий сохраняются для
обратной совместимости.

Категории ограничены enum канонической схемы. Ранее смена языка ошибочно
писалась с категорией `session`. Producer, compactor и ручной импорт
преобразуют только этот известный legacy-алиас в `lifecycle`, сохраняя
`eventId` и время. Неизвестные категории по-прежнему отклоняются; серверная
валидация и запрет PII/сырых медиаданных не ослабляются.

## Завершение и повторная отправка

`finishSession()`:

1. Использует один стабильный `finishAttemptId`.
2. Останавливает центральный видеопайплайн, RT listeners, QC и запасные loops.
3. Финализирует BPM/respiration, emotions, body pose, blink dynamics и PERCLOS,
   затем строит heatmap и attention aggregates.
4. Останавливает все camera tracks и очищает `video.srcObject`.
5. Показывает финальный экран.
6. Отправляет итоговый payload с заголовком
   `Idempotency-Key: <finishAttemptId>`.

До подтверждения `POST /ingest` подготовленный итоговый payload и завершённый
checkpoint хранятся в IndexedDB. Повторная отправка использует этот payload,
а не пересчитывает агрегаты по потенциально неполной восстановленной копии.
После перезагрузки отправка ожидает загрузки participant shell и привязки
приглашения (`wecog:participant-ready`), затем повторяется с тем же ключом. API
возвращает `200` без повторных записей для уже принятого ключа и `409` для
другого ключа завершённой сессии. Первая запись возвращает `201`.

Checkpoint-записи сериализованы: явный `await saveCheckpoint()` гарантирует,
что более ранняя запись завершится и последняя версия state будет сохранена.
Высокочастотные gaze/EAR samples дописываются в IndexedDB дельта-чанками
вместе с атомарным checkpoint, а не копируются целиком каждые 5 секунд. После
reload samples восстанавливаются, незавершённый блок помечается невалидным,
добавляется в очередь повтора, а участник возвращается к camera precheck и
персональной калибровке.

Terminal save/clear дополнительно ожидает уже запущенную periodic checkpoint
операцию. Поэтому медленная фоновая запись состояния `running` не может
завершиться после `completed` и восстановить устаревшую незавершённую сессию.
Все одновременные callers фонового сохранения получают обработанный результат
ошибки, без отдельного необработанного rejection.

При перемещении начала ограниченного gaze/EAR-буфера его чанки атомарно
перезаписываются в соответствии с текущим окном. Уменьшение массива при штатном
retention больше не считается повреждением checkpoint. Это не снимает лимит
буфера и не превращает его в полный архив отсчётов длительной сессии.

При отказе IndexedDB используется минимизированная резервная копия в
`sessionStorage` текущей вкладки: RT, прогресс, согласие, lifecycle и уже
подготовленный итоговый payload. Диагностические массивы отсчётов исключаются;
восстановление явно помечается `storageRecovery.compactCheckpoint`, а участнику
показывается предупреждение о неполных сырых отсчётах. Если недоступны оба
хранилища, начало сессии не выдаёт ложной гарантии сохранения. На финале ошибка
локальной записи не блокирует итоговый экран, скачивание и попытку ingest.
Закрытие вкладки уничтожает sessionStorage; это не долговременный серверный backup.

`experimentMeta.protocolProgress` хранит ID/позицию блока, сигнатуру
последовательности и immutable invitation code. После восстановления завершённые
RT не очищаются; незавершённая попытка повторяется по обычным QC-правилам.
Последний `finish`-блок автоматически запускает сохранение без дополнительной
кнопки. `finish` внутри последовательности не пропускает последующие задания.
Стабильный входной код используется для распознавания своего checkpoint, но
не изменяет серверную immutable-привязку сессии.

Промежуточные и fallback-файлы автоматически не скачиваются. Локальная
выгрузка остаётся явным действием участника на финальном экране.

## Typed transport и ingest token

### Промежуточные серверные копии (2026-10-18)

После согласия тот же transport отправляет накопительный `session_feature.v1`
каждые 30 секунд, между блоками и после восстановления сети. Поле `delivery`
содержит `schemaVersion=session_delivery.v1`, положительный целочисленный
`sequence` и `kind=checkpoint|final`. У checkpoint lifecycle остаётся
`in_progress`, отсутствует finish-key и не выставляется `stopped_at`.
Это ещё не завершённый результат; в аналитике включите незавершённые сессии.

В шаге контроля качества исследователь может выключить уведомления об успешной
промежуточной отправке: `settings.persistence.showBackupNotifications=false`.
Опция сохраняется в черновике и неизменяемой публикации. Она не меняет период,
состав или обязательность резервного сохранения. При отсутствии настройки
уведомления остаются включёнными. Предупреждения об ошибках отправки, недоступном
локальном хранилище и восстановлении сессии этой настройкой не скрываются.
Состояние `saving` не считается ошибкой и не показывает предупреждение.

При входе по постоянной ссылке перед согласием повторно запрашивается актуальная
публикация (`no-store`). Для admission и ingest используется только неизменяемый
`code`, возвращённый API, а не введённый код постоянной ссылки. Уже допущенная
сессия при перезагрузке остаётся на своей версии по `session_id`; перепривязка
исторических результатов к новой публикации не выполняется.

Одновременно отправляется только одна промежуточная копия; номер записывается
в локальный checkpoint до отправки. Ошибка сети не блокирует выполнение пробы.
API атомарно сравнивает номер с сохранённым payload: меньший номер и повтор
номера с другим содержимым дают 409. Идентичный повтор даёт 200 без перезаписи.
SHA-256 нормализованного входного пакета записывается сервером в
`experimentMeta.serverDeliveryDigest`; присланное клиентом значение не доверяется.
Финальный ingest имеет приоритет над промежуточными; после завершения старые
копии не изменяют результат. Старые финальные клиенты без delivery совместимы;
неверсионированная промежуточная запись не заменяет уже нумерованную.

Агрегация heatmap/attention/RT alignment выполняется в module Worker; это не
второй видеопайплайн и не новая модель. В Worker передаются только локальные
измерительные данные, затем на API отправляются типизированные агрегаты.
При недоступном Worker копия явно маркируется
`backupScope=light_summary_without_signal_series`; отсутствующие signal series
не выдаются за нулевые измерения. Python RT-анализ запускается при финализации,
не на каждом промежуточном сохранении. Перенос объектов/JSON всё ещё имеет цену;
точность RT на слабых устройствах требует отдельного нагрузочного benchmark.

Это последняя принятая накопительная копия, не полный архив всех временных
точек и не обещание нулевой потери. При доступной сети целевой интервал 30 с;
в офлайне, при перегрузке и фоновой приостановке вкладки задержка больше.
При отказе браузера исследователь видит уже принятый неполный результат.
Автоматического продолжения на другом компьютере без локального состояния нет.

### Правила QC Протокола

Новые публикации включают `settings.qualityControl` с
`schemaVersion=protocol_quality.v1` и `rules`. Поддержаны `gazeValid`,
`faceDetected`, `fpsStable`, `lighting`; правило содержит `enabled`, `threshold`,
`hardStop`. Проценты ограничены 0..100, FPS 0..60. Это дополнительные правила:
отключение правила не отключает базовые проверки или отбраковку сигнала.

Версия метода `cumulative-observed-metrics-1.0.0` использует накопленные
`gazeValidPct`, `faceVisiblePct`, `analysisFps`, `illuminationOkPct`. Освещение
означает долю кадров с допустимым светом, не произвольную оценку яркости.
Нет измерения означает `no_data`, а не успешную проверку. Live-проверки
начинаются после 10 секунд/10 кадров и запуска протокола; нарушение должно
сохраняться 3 секунды. Пауза очищает отсчёт выдержки. Эти длительности являются
версионированным инженерным правилом, не клинически валидированным порогом.

Hard stop завершается после текущей пробы, без скрытой остановки таймера.
Причины, невалидная попытка и отказ от очереди повторов сохраняются в событиях.
`experimentMeta.protocolTermination.reason=quality_stopped` отличает прерванный
протокол от полного прохождения. Запись сессии финализируется и отправляется,
но researcher status равен `aborted`, и без include-incomplete она исключена.
API заново оценивает метрики по правилам immutable invitation, не по текущему
черновику или присланной отметке «QC пройден». Это проверка правил, не независимая
верификация достоверности измерений, присланных браузером.

### Диагностика Сохранения

Consent различает недоступность локального хранилища, сеть, отказ доступа,
истечение/лимит приглашения, серверный сбой и отклонение формата. Final upload
различает те же серверные категории и оставляет скачивание JSON доступным.
События содержат этап, безопасный код и HTTP-статус, а не произвольный текст
ошибки с путями или токенами. Уведомления резервного копирования не показываются
поверх активной пробы; они не являются подтверждением финальной отправки.

Новых SQL-миграций для этих трёх изменений нет; используется существующий
session_features в транзакции ingest. Предыдущая migration 18 остаётся обязательной.
Обновлять API и versioned static files согласованно, cache version `20261018-3`.

Единственный сетевой transport participant-клиента находится в
`apps/participant-web/js/session-runtime/ingest-transport.mjs`. Он принимает
только `session_feature.v1`; `web-page/data-sender.js` является совместимым
facade и не содержит собственного `fetch('/ingest')`.

Участник при подтверждении согласия, до длительного эксперимента, обменивает код приглашения и
`session_id`:

```text
POST /invitations/by-code/:code/ingest-token
```

Полученный server-issued JWT связан с session, invitation, protocol и project.
Admission допускает один короткий повтор при временной сетевой/серверной ошибке
с тем же session ID; повтор не резервирует дополнительный run. Ошибки доступа
не повторяются. Если `Retry-After` превышает короткое окно повтора, запрос не
отправляется досрочно; участник получает обычную ошибку начала сессии.
Token mismatch на `/ingest` возвращает `409`, отсутствующий или истекший token
возвращает `401`. Staff ingest разрешен только для project-scoped сессии,
ранее созданной через `/sessions/start`.

### Асинхронный RT-расчёт при сохранении

Checkpoint не запускает Python. Для остальных ingest API сначала выполняет
read-only проверку доступа и привязки, затем рассчитывает RT вне транзакции БД.
Перед атомарной записью он повторяет проверки под session lock: token/role,
membership, participant, invitation, protocol snapshot, delivery и idempotency.
Отзыв доступа или изменение контекста за время расчёта не пропускает запись.

На один API-процесс допускается один RT-процесс и восемь ожидающих заданий.
Общий deadline, включая очередь, составляет 60 секунд. Весь пакет блоков
обрабатывается одним запуском Python; формулы и `rt_features.v1` не меняются.
Добавлен optional provenance `adapter_version: rt_event_adapter.v2`: пустой
блок не создаёт вымышленную пропущенную пробу, результаты соседнего блока не
используются вместо отсутствующих. Legacy unscoped rows назначаются блоку
только при единственном, однозначном блоке протокола. У старых результатов
версии адаптера нет; исторические записи автоматически не пересчитываются.
Вход Python и каждый выходной поток ограничены 10 MiB. Это технический лимит
расчёта, не новый лимит файлов или веса протокола. При разрыве соединения
ожидающее задание снимается, активная группа процессов завершается.

- `503 rt_analyzer_busy/timeout/failed/invalid_output/output_limit`: итог не
  подтверждён, `Retry-After: 5`; сохранить локальный пакет и повторить тот же
  запрос с прежним `Idempotency-Key`, без нового admission.
- `422 rt_analyzer_input_limit`: развёрнутый RT-вход слишком велик; данные
  checkpoint не удаляются. Нельзя исправлять это отбрасыванием проб молча.
- `409 rt_analysis_context_changed`: протокол или scope изменились во время
  расчёта; автоматическое применение рассчитанных по другой версии метрик запрещено.
- `409 final_delivery_stale`: более свежий checkpoint нельзя заменить старым
  финальным пакетом. Требуется сверить состояние и подготовить актуальный пакет,
  а не бесконечно отправлять старый. Legacy final без `delivery` допускается,
  только если ещё не сохранён sequenced checkpoint.

Ошибка не отмечает сессию завершённой и не заменяет принятую промежуточную копию.
Уже закоммиченный final остаётся sealed: повтор своего ключа возвращает ACK,
другого — conflict. Отсутствующий Python, как прежде, явно отмечает RT-метрики
`analyzer_unavailable`, а не подменяет их нулём. `/health` использует один
асинхронный probe с timeout 2 секунды и cache 30 секунд; абсолютные пути и
native stderr в публичный ответ не попадают.

Перед admission проверяется фактическая запись checkpoint и читаемая ссылка на
него в sessionStorage. До подтверждения admission локальный `admissionPending`
не позволяет переход к регистрации, запуск фоновой отправки или восстановление
как уже допущенной сессии. Повтор входа использует прежние session/participant ID.
После успешного admission checkpoint записывается ещё раз. Этот служебный флаг
не является полем API-контракта и не заменяет проверку токена на сервере.

Открытие IndexedDB и каждая транзакция ограничены 10 секундами. Зависшая запись
прерывается перед переходом к компактному резерву; поздно открытое соединение
закрывается. Ошибка чтения существующего checkpoint блокирует новое прохождение
с объяснением: старые данные не очищаются и не заменяются пустой сессией.
Компактный резерв сохраняет RT и подготовленный итоговый пакет, но не обещает
полноту всех исходных отсчётов. После восстановления незавершённой сессии
`experimentMeta.storageRecovery.signalSeriesIncomplete=true` переносит этот факт
и список пропущенных рядов в последующие агрегаты/JSON; это не нулевые измерения.
Уже подготовленный итоговый пакет при этом не пересчитывается и не изменяется.
Отсутствие читаемой ссылки на точку восстановления
также не считается успешной локальной записью.

Сетевой deadline включает чтение тела ответа: 30 секунд для JSON. HTTP 200/201
сам по себе не подтверждает сохранение. Transport требует канонический ответ
`ingested=true`, те же session ID, lifecycle и finish-key, корректные поля
подтверждения. Пустой ответ, HTML от прокси или чужой session ID оставляют пакет
неотправленным для повтора. Ошибка UI-уведомления не отменяет реальное
подтверждение. Правила действуют и для ручного импорта JSON в кабинете.

Для ingest учитывается `Retry-After`, включая последующие автоматические циклы,
ручные повторы и перезагрузку при доступном sessionStorage. Длинная задержка
завершает текущий цикл, а не сокращается до раннего повтора. Итоговый пакет и
ключ остаются неизменными. При повторе API может дополнить сохранённый payload
своими вычисленными RT/QC-полями; это не изменение клиентского пакета повтора.

Полная матрица операций и tenant scope описана в
`docs/api/authorization-matrix-v1.md`.

## Непрерывные сигналы

| Module | Период | Итог |
| --- | --- | --- |
| gaze | каждый новый face frame | raw/corrected/display, confidence, OOD, head |
| blinks | каждый новый face frame | count, duration, amplitude, opening speed |
| PERCLOS | вся сессия | rolling windows 30s/60s |
| emotion | около 5 Hz | valence/arousal/confidence summary |
| body pose | около 5 Hz | torso movement, bursts, lean, confidence |
| BPM/respiration | непрерывный rPPG | run и session summaries |
| RT | input events в trial | typed input events и protocol RT features |
| audio | окна по 10 секунд | локальные biomarker/QC aggregates, без PCM |
| multimodal | каждый принятый gaze frame | gaze + emotion + head/body по общему времени |

В аналитике «Сессия» и «Группа» блок «Фоновые показатели» показывает сохранённые
ЧСС/дыхание, моргания/PERCLOS, движение корпуса и proxy мимики. Вычисления
доступности общие для API и UI: `apps/shared/passive-metrics.js`. Отсутствующие
данные не заменяются нулём; общий статус QC сессии не подтверждает точность
отдельного физиологического канала. Исторические записи показывают только
сохранённые сводки с версией метода, без выдуманного восстановления сигналов.

В «Связанности» выбор маркера, строки или точки синхронизирует детали одной RT
пробы; доступны клавиатура, переходы между пробами и увеличение временной линии.
Дыхание добавлено как опциональный канал `event-windows-1.1.0`, старые отчёты
1.0.0 поддерживаются. Полносессионные средние нельзя применять к выбранному
интервалу. Короткое окно RT не является валидированным окном физиологического
ответа; для rolling ЧСС/дыхания UI не вычисляет корреляцию и HRV.

Все непрерывные сигналы получают время из одного monotonic clock. Multimodal
сопоставление принимает ближайший сигнал только в пределах 100 мс, не
подставляет эмоцию при отсутствии/низкой уверенности и хранит gaze в
нормализованных координатах конкретного стимула. Gamer/head-body слой включается
отдельным protocol feature flag.

Сырые video frames и audio PCM не включаются в payload. Аудиоанализ имеет
таймаут, а отказ `AudioWorklet` переключает сбор на `ScriptProcessor`, поэтому
ошибка необязательного модуля не блокирует завершение сессии.

## Feature flags и согласие

Исследователь задаёт флаги в `protocol.settings.featureFlags`:

```json
{
  "audio": false,
  "multimodal": true,
  "bodyMovement": true,
  "gamerMode": false
}
```

`audio=true` только показывает участнику отдельный необязательный пункт
согласия. Без явного `audioConsent.granted=true` браузер не запрашивает
микрофон. Отказ или отсутствие поддержки переводят аудио в degraded status,
но не бракуют остальные измерения. Debug/raw capture запрещён независимо от
feature flags.

## Интеграция нового теста

Перед показом инструкции:

```js
runtime.enterInstruction({ blockId, blockType });
```

Перед первым стимулом:

```js
const attempt = runtime.beginBlock({ blockId, blockType });
```

После последнего стимула:

```js
const decision = runtime.completeBlock({ success: true });
if (decision.repeatRequired) {
  await runtime.promptRepeat(blockId);
  // Запустить тот же блок заново. attempt увеличится автоматически.
}
```

Не создавайте второй `analyzeFrame` loop, если
`runtime.isAnalysisRunning()` возвращает `true`.

```bash
# API
cd apps/api
cp .env.example .env
npm ci
npm run migrate:up
npm start

# статика, из корня репозитория
python3 -m http.server 8080
```

Участник:

```text
http://localhost:8080/apps/participant-web/run_new.html?code=<КОД>
```

Прямой локальный экран для UI/smoke-проверки:

```text
http://localhost:8080/apps/participant-web/mvp_with_precheck_1-updated.html
```

Production-доступ без приглашения не разрешён; bypass действует только на
`localhost` и `127.0.0.1`.

MediaPipe runtime, WASM и модели Face/Pose размещены на application origin.
CDN fallback в каноническом participant flow отсутствует.
Participant entry pages задают `Referrer-Policy: no-referrer`, поскольку код
приглашения является bearer credential и находится в URL.

Production nginx должен отдавать `.mjs` как JavaScript и разрешать
`camera=(self), microphone=(self)` только participant-страницам. Готовый
фрагмент: `deploy/nginx-participant-media.conf`. API и researcher routes не
должны получать доступ к media devices.

## Длинные сессии и signal summaries (2026-10-19)

- `gaze-history.mjs` обновляется перед raw retention. `heatmapState` сохраняет
  фиксированные сетки, счётчики и состояние текущей фиксации; не raw-точки.
  Checkpoint worker и final используют одну реализацию. Повторные или
  регрессирующие timestamps не увеличивают статистику и отдельно считаются.
- Метод fixation heatmap `1.2.0`: duration x quality по centroid фиксации,
  не raw-sample density. Минимальная реальная протяжённость фиксации 100 ms;
  одиночная точка после паузы не является фиксацией. Стандартные и загруженные
  стимулы проходят один путь с media-content rect и pinned stimulus version.
  Quality применяется по актуальной на момент отсчёта validation RMS; новая
  калибровка влияет на будущие вклады, не перемасштабирует прошлые.
- Локальные context limits: 2000 показов, 200 блоков, grid dimensions <=128.
  Canonical path использует 32x18. Список фиксаций ограничен 500 на показ,
  wire-отчёт - 200 показами. Общий wire-бюджет - 4000 подробных фиксаций,
  распределённых между показами; полные grids/counts не сокращаются из-за этого
  лимита. `fixationsTruncated`/`presentationsTruncated` означают неполноту
  подробностей, а не нулевые события. Полная сетка показов,
  попавших в accumulator, и общие counts продолжают накапливаться. AOI для
  усечённого списка возвращает `no_data`, не заниженное значение.
- `heatmapState` и `continuousSignalState` остаются локальными checkpoint
  полями. На API идут существующие aggregate objects, не raw media/landmarks.
  Миграция БД и новые top-level wire fields не нужны.
- `continuous_signals.v2`: свежие ЧСС/дыхание считаются онлайн; hold исключён
  из mean/count. Дыхание требует опубликованного сигнала с confidence >=0.20
  в существующем диапазоне 6-24/min. Raw и low-confidence peak не fallback.
  Spectral resampling требует реально покрытого окна, возрастающих timestamps
  и отсутствия больших пропусков. Порог качества не снижен.
- Накопленные counts/mean/min/max сохраняются после reload; means объединяются
  с весом по числу валидных измерений. Серия rPPG/дыхания ограничена 7200
  диагностическими записями. `range_scope=retained_samples` отличает диапазон
  этой серии от cumulative статистики. Body velocity P95 также имеет scope
  `retained_samples`; gaze dynamics на rolling raw buffer имеют отдельный
  coverage marker. Полная тепловая карта не делает все raw-derived метрики
  автоматически полносессионными.
- Compact fallback сохраняет accumulator, если хватает квоты; пропущенные
  raw series по-прежнему явно помечены. При исчерпании всех хранилищ остаются
  действующие предупреждение, финальная отправка и JSON download. Удалённые
  исторические raw точки восстановить задним числом невозможно.

## Незакрытые production gates

- gaze thresholds требуют baseline-versus-new benchmark минимум на пяти
  участниках и нескольких типах камер/освещения;
- полный role x operation x own/foreign tenant workflow должен пройти как
  HTTP E2E на staging, а не только через permission/unit tests;
- многочасовые сессии требуют browser memory/IndexedDB quota stress-теста:
  chunked checkpoint исключает повторное копирование, но активные raw arrays
  и восстановление после reload по-прежнему занимают память;
- multi-instance API требует распределённого rate limiter;
- admission атомарно резервирует run после согласия и до испытания; требуется
  утвердить retention/monitoring abandoned session. Автоматическое освобождение
  отключено, чтобы reload и запоздалый ingest не создавали oversubscription;
- production должен подтвердить работу используемой HttpOnly/SameSite staff
  cookie и CSRF за реальным reverse proxy, включая logout и смену пароля;
- обязательны CI, review ответственного, staging smoke и формальная приёмка.
