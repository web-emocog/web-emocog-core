1. Разрешены 29 конфликтных файлов с сохранением обеих сторон: новые
   upstream-модули и правила качества, локальные ограничения приватности,

### Уточнение по №151

В Windows-прогоне с хорошим светом среднее по issue составляет 22,87 FPS,
а 26 FPS в диагностике JSON относится к последнему окну, не ко всей
сессии. По накопленным таймингам первичная обработка занимает в среднем
30,85 мс, из них измеренная стадия лица 30,15 мс; сегментация в отдельном
канале около 81,8 мс на запуск. Это времена стадий вместе с передачей
кадра/ожиданием, не чистое время модели. Из них нельзя доказать, что
виновата только сегментация или что получится гарантированные 32 FPS.

Все пять записей используют старый `protocol_signals.v1`. Новый профиль
`v2` снижает частоту вспомогательных вычислений и делает тело опциональным,
но опубликованные `v1` не мигрируются молча. Сравнение профилей должно
сохранять измерительный контракт и отдельно учитывать возможную потерю
временной детализации. Исходные записи с landmarks и идентификаторами
оставлены вне Git в приватной `.tmp/issue151-private` родительского проекта.

Наборы частично пересекаются, поэтому их суммы не являются числом
независимых функций. Первый браузерный запуск нашёл описанную выше
ошибку видимости медиа. Другой прогон потерял общий статический сервер;
затем обнаружилась неполная передача параметров синтетического аккаунта
тестов публикации. Исправления проверяются отдельными процессами и
серверами; эти сбои стенда не скрываются как успешные прогоны продукта.

Проверки ошибок стимулов включены в постоянную конфигурацию
`playwright.production-audit.config.ts`, а не только во временный запуск.
Основные команды для повторения из соответствующих папок:

```sh
# apps/api: PostgreSQL запускается только с отдельными тестовыми БД
npm test
npm run test:postgres
npm run test:rt-python
node scripts/release-audit.js

# apps/autotests: наборы с одним портом запускать последовательно
npx tsc --noEmit
npx playwright test -c playwright.production-audit.config.ts
npx playwright test -c playwright.staff-regression.config.ts
RUN_WORKER_REGRESSION=1 npx playwright test -c playwright.workers.config.ts
npx playwright test -c playwright.fps.config.ts

# корень: не перезаписывать исторический отчёт от 6 ноября
PHYSIOLOGY_BROWSER_REPORT=/tmp/physiology-recheck.json node scripts/long-session/run-physiology-browser.mjs
```

Живые наборы требуют предварительного создания тестовой БД и фикстуры
`scripts/seed-live-stimulus-fixture.cjs`. Для проверки участника используется
`RESILIENCE_TEST_DATABASE_URL` с отдельной `protocol_fixes_test`;
для медиа `LIVE_STIMULUS_FIXTURE`. Проверка совместной публикации требует
`RUN_RESEARCHER_CONTRACT=1`, `WECOG_AUDIT_API_BASE`, идентификатора проекта
и `EMOCOG_RESEARCHER_*` / `EMOCOG_PEER_*` из синтетической фикстуры.
Чужие или production-аккаунты для этих команд использовать нельзя.

## Границы вывода

В проверенных сценариях объединённый кандидат работает. Утверждать
отсутствие любых багов, научную точность или готовность всех issues к
закрытию нельзя. Реальная камера, микрофон и production не использовались.
WebKit здесь является автоматизированным движком, а не установленным
Safari с той же камерой и драйвером. Аппаратная приёмка №132/151 и
эталонная физиология №146 остаются обязательными. Инструкция:
[проверка на реальных устройствах](../operations/real-device-acceptance.md).

№143 исключён из анализа и оценки готовности. Уже присутствующие в
`develop` изменения сохранены; общий регрессионный прогон не означает
закрытия или научной приёмки этого issue.
