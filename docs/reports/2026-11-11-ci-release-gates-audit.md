в успех и не отменяет требования обязательного release gate.

Закрытые пробелы:

- В PostgreSQL gate есть реальный restore строк и байтов загруженного
  стимула. Проверяется и отрицательный сценарий: подмена байта при
  сохранении размера должна остановить резервное копирование. Тест
  явно требует disposable БД и создаёт целевую БД на том же loopback PostgreSQL.
- HTTP-контракт проверяется один раз без браузера и статического сервера.
  Сквозной сценарий доставки запускает собственный loopback-сервер на
  4229 и разрешает в тестовом API только его CORS origin. Основной
  браузерный набор и Worker-набор не удаляют артефакты друг друга.
  Изолированные наборы используют существующий loopback-сервер с
  очередью 128 подключений, а их артефакты хранятся под
  `apps/autotests/test-results/`, откуда CI забирает их при отказе.
- Ручной workflow WebKit проверяет калибровку и диагностики взгляда;
  ручной Windows workflow проверяет реальный классический scrollbar в
  Chromium. Это функциональные тесты, не проверка точности камеры.
- Проверка `bash -n` проходит отдельно по каждому deployment-скрипту.
  RT smoke включает существующий Python regression callback без GUI.

Продуктовый runtime, схемы, роли, production-конфигурация и качество
измерений не изменены. Production и rollback не запускаются для аудита.
Локальные прогоны не заменяют проверку на GitHub-hosted Linux и Windows;
внешний сбой зеркал всё ещё может остановить workflow, если пакеты
действительно отсутствуют.
