# Локальный аудит основного сценария: 5 ноября 2026

Работа выполнена локально в `feature/signal-quality-profiles`. На GitHub и
production ничего не отправлено. Это усиление кандидата, не объявление продукта
полностью готовым к открытому платному запуску.

## Исправления

### Загрузка и версии стимулов

- Вместо исходного имени в storage используется UUID. Длинное имя больше не
  вызывает `ENAMETOOLONG`; отображаемое имя хранится отдельно, максимум 512 символов.
- Ограничены поля multipart: один файл, восемь полей, 256 KiB на поле.
  PDF/PPT/PPTX проверяются по расширению до записи документа.
- Имя документа передаётся отдельным UTF-8 полем `original_name`, чтобы кириллица
  не портилась при разборе multipart-заголовка. Старые клиенты без поля совместимы.
- Из публичных staff-описаний удалены оба варианта внутреннего пути:
  `content_path` и `contentPath`.
- Список библиотеки читает версии одним JOIN вместо отдельного SQL-запроса
  на каждый файл. Одновременно выполняется не больше восьми проверок файлов.
- Готовое проверенное превью не ждёт общей блокировки записи медиа. Генерация
  и backfill остаются внутри согласованной границы DB/uploads backup.
- При откате операции удаляются также новые превью, не только оригиналы.
  Проверена ошибка на второй странице настоящего PDF: ранее созданные файлы
  этой операции удаляются, прежние файлы сохраняются.
- При потере подтверждения COMMIT файлы не удаляются: возвращается
  `media_write_uncertain`. Нельзя считать такой исход доказанным откатом или
  автоматически повторять мутацию. Возможные сиротские файлы требуют сверки.
- Пакет загружается последовательно. Каждый подтверждённый файл сохраняется
  в интерфейсе до получения необязательного превью. При ошибке выводится число
  сохранённых файлов; следующие файлы не отправляются, прежние не повторяются.
- Выбор файлов в интерфейсе больше не обещает поддержку произвольных форматов
  изображения, видео или TXT. Окончательная проверка остаётся на API.

Лимит отдельного файла не повышен: по умолчанию 50 MiB. Новых зависимостей,
моделей, миграций и изменений схемы SessionFeature нет.

### Аналитика и импорт

- Импорт фиксирует аккаунт, API, страницу, проект и протокол до чтения файла.
  При смене контекста он не продолжает запросы и не меняет новый экран.
- Загрузка результата использует общий staff HTTP с отменой и сроком ожидания,
  включая чтение ответа. Не используется отдельный не привязанный к экрану fetch.
- Повторный клик импорта не запускает вторую операцию одновременно.
- Отмена сохраняется даже при возврате на прежний экран; после отмены можно
  явно выбрать файл повторно, не оставаясь в зависшем статусе «загрузка».
- Поздняя ошибка старого запроса фильтров не попадает в новый контекст аналитики.
- Регрессиями проверены публикации и их версии, AOI/тепловые карты, выборка и
  экспорт, отсутствующие физиологические данные, промежуточные и конечные копии.

### Графические режимы и модули

- GPU не означает NVIDIA/CUDA: на этом Mac замер зафиксировал
  `ANGLE Metal Renderer: Apple M4 Pro`. Браузер может также использовать
  программный WebGL; поле delegate описывает запрошенный режим модели, а не
  доказывает наличие физического ускорителя.
- При ошибке GPU при запуске или инференсе лица выполняется ограниченный переход
  на CPU с теми же весами и временными метками кадра, внутри прежнего Worker.
  Для повторного расчёта используется уже захваченный canvas, а не обновившееся
  видео со старой временной меткой. Тест меняет исходный кадр во время сбоя и
  проверяет фактический пиксель, полученный CPU-моделью.
- Три последовательные ошибки инференса закрывают неисправную модель до явного
  reset/retry. Нет бесконечного создания моделей в каждом кадре; успешный кадр
  сбрасывает счётчик последовательных ошибок.
- Отсутствие WebGL даже при CPU delegate может мешать подготовке изображения в
  закреплённом MediaPipe. Это проверено принудительным отказом обоих видов canvas
  в трёх движках. Недоступность обработки обозначается технической ошибкой.
- Precheck не проходит по устаревшим зелёным индикаторам при ошибке анализатора.
  В русском и английском интерфейсе есть отдельное объяснение технического сбоя.
- При ошибке основного анализа `SessionQualityDetector` не создаёт дополнительных
  событий «нет лица», «лицо закрыто», «неправильная поза». Реальное отсутствие
  лица без ошибки модели продолжает проверяться прежним правилом. Формулы
  итоговых долей пригодных кадров и пороги качества не ослаблены: технически
  испорченные данные не становятся валидными.
- Не запускается вспомогательная обработка ошибочного основного кадра.
  Сбой сегментации также не выдаётся за нормальное отсутствие окклюзии в precheck.
- Основной анализ не ждёт сегментацию/корпус. Single-flight, timestamps и
  владение общими пикселями сохранены; GPU-сегментация на Chromium/Mac
  автоматически не включена.

Официальные источники:
[MediaPipe Web setup](https://developers.google.com/edge/mediapipe/solutions/setup_web),
[ANGLE backends](https://github.com/google/angle).

## Проверки и воспроизводимость

Использована отдельная PostgreSQL 16 в Docker, отдельные API/uploads и
синтетические аккаунты owner/peer/outsider/admin. Рабочие аккаунты, БД и файлы
пользователей не изменялись. Настоящие камера и микрофон не включались.
Тестовый ingest rate limit соответствует CI; продуктовые лимиты не изменялись.

Команды для итогового набора:

```sh
cd apps/api
npm test
S2_TEST_DATABASE_URL=postgres://... npm run test:postgres

cd ../autotests
npm run typecheck
LIVE_STIMULUS_FIXTURE=/private/path/synthetic-fixture.json \
  npx playwright test --config=playwright.production-audit.config.ts
RUN_WORKER_REGRESSION=1 npx playwright test --config=playwright.workers.config.ts
npx playwright test --config=playwright.staff-regression.config.ts tests/signal-quality-profiles.spec.ts
```

Fixture создаётся `scripts/seed-live-stimulus-fixture.cjs` только на отдельной
тестовой БД; её `apiBase` должен указывать на изолированный API. Конфигурация
браузера сама занимает loopback-порт 4173 и не переиспользует чужой сервер.
Образы API включают настоящие FFmpeg/ffprobe и Poppler. Большой браузерный
набор не заменяет проверку API без ограничений тестового окружения и нагрузочные
испытания production-конфигурации.

| P1 | Реальные устройства | Установленные Safari/Chrome/Firefox, Windows/Intel/AMD/Apple Silicon, слабые/программные графические режимы; эксперимент GPU segmentation требует matched-frame QC/mask приёмки |
| P1 | Научная точность | Независимая синхронная разметка/eye tracker/ЭКГ или PPG/дыхательный пояс, очки, движения, свет, разные группы участников |

ЧСС/дыхание по файловому видео в данном прогоне проверяются как технические
выходы каналов, не как валидированные значения на человеке. Эмоции FACS являются
модельными оценками выражения лица, не объективным настроением. Нет оснований
объявлять подтверждённой точность взгляда, эмоций, ЧСС или дыхания.

## Выкатка и откат

Сначала review и CI, затем develop и ограниченная приёмка. Не включать
экспериментальную GPU-сегментацию для всех и не менять старые публикации на v2.
При отказе откатываются согласованные API/static-версии. Файлы исторических
публикаций и версии БД не удаляются. Выбор v1 в следующей публикации возвращает
прежнюю политику частот, но не отменяет отдельные исправления сохранности данных.
