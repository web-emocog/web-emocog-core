# Issue #143: локальная проверка автоматического выбора eye-patch

Ревизия `20261110-143t`, только localhost. Никаких изменений
participant default, QC, аналитики, API или рабочего непрерывного блока.
Парный кандидат помог в низкой посадке (237→154 px на общих кадрах),
но ухудшил обычную и вернувшуюся посадки. Поэтому две новые оценки
считаются параллельно обычным моделям, не заменяя их.

## Выбор по изображению, без текущей позы или цели

Из пяти вспомогательных пар берётся средняя разность признаков.
Из неё исключается направление различий между обычными калибровочными
целями. Направление должно согласоваться не менее чем у четырёх из пяти
оставляемых вне fit пар; минимум четыре alternate anchors должны
выходить за обычный диапазон красной сетки. Это калибровочная проверка
разделимости, не подтверждение точности. При перекрытии выдаётся
технический JSON без зелёных измерений. Векторы, границы и веса не
выгружаются.

После красных точек функция выбора заморожена. Она использует признаки
того же кадра; не читает положение головы, таймер, цель, AOI, прошлый
прогноз или смену посадки в UI. На обычных и далёких неизвестных
значениях вес парной оценки ноль. Умеренные изменения дают плавное
смешивание двух **raw** предсказаний только внутри экрана. Если обычный
прогноз пропущен, обе дополнительные оценки тоже отсутствуют.

Есть две оценки: строгая сохраняет классификацию «на экране/за экраном»
обычного patch. Вторая в знакомом режиме может принять внутренний
парный прогноз вместо вылета, только если отдельно обученный Gradient
All также уверенно внутри и обе точки близки по координатам. Без
сопоставимых калибровочных кадров для Gradient All эта ветка отключается
и не требует дополнительных кликов. Согласие двух методов не равно
подтверждённой точности; эта ветка никогда не выбирается production.

Дополнительные оценки сохраняются как `*.raw` в окнах A–B–A;
не участвуют в коррекции и не меняют исходные сигналы. На общей выборке
доступны сравнения с исходным eye-patch, парным и iris baseline.
Коды действий и counts ограничены по окну; никаких изображений,
координат отдельных кадров, весов или отправки в API.

## Синтетический допуск к проверке с камерой

`node scripts/reference-data/issue143-patch-background-synthetic.mjs`,
v5. В обычных искусственных условиях оба селектора совпали с полным
patch на всех 144 кадрах. При знакомом изменении строгий вариант
сохранил 144/144 ложных вылетов; проверка Gradient All исправила 63
из них и не добавила ложных попаданий внутрь в этих восьми ближних
и восьми дальних заэкранных примерах. На опорном частичном перекрытии
нижняя ошибка 354→116 CSS px на общих кадрах, но ошибка всей сетки
выросла 215→236. На сильном изменении ни одна ветка не устранила
провал. Искусственные результаты не подтверждают specificity,
точность на людях или работоспособность в AOI.

## Результат двух реальных запусков `143t`

Оба Safari-прогона остановились перед зелёными целями с
`overlapping_reference_range`. В каждом были 50/50 контрольных
кликов без повторов, все 10 вспомогательных окон и ранг 3; направление
разности было согласованным на 5/5 пар. Тем не менее за диапазон
красной сетки вышли только 1/5 и 0/5 альтернативных окон. Это не отказ
камеры, не плохое выполнение и не недостаток кликов: один общий балл
яркости смешал изменение посадки с обычной вариацией взгляда. Не
понижаем порог и не просим повторять эту версию. В одном прогоне
Gradient All дополнительно не набрал общих калибровочных кадров.
