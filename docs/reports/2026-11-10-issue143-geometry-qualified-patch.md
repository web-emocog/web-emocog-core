# Issue #143: геометрия лица как отдельный квалификатор для сравнения

Ревизия `20261110-143u`, локальный диагностический эксперимент.
Рабочая gaze-модель, пороги QC, API и непрерывные опубликованные блоки
не менялись. Участнику в рабочем протоколе этот эксперимент недоступен.

## Доказательства и ограничения

В двух реальных `143t` после 50/50 красных нажатий посадки не
разделились по признакам eye-patch: 1/5 и 0/5 альтернативных точек
оказались вне диапазона обычной калибровки при требовании не менее 4/5.
Зелёных измерений нет. Это не повод уменьшить защитный порог.

`node scripts/reference-data/issue143-geometry-audit.mjs <JSON>`
проверяет отдельный channel `eyeMidY` — высоту центра четырёх уголков
глаз в кадре. Шесть уже имеющихся завершённых A–B–A (три записи одного
пользователя, три — тестировщиков) показали разрыв между нижней
посадкой и объединением «обычно/вернулся»: 0,041–0,067 высоты кадра.
Это расстояние между объединениями интервалов «среднее ± 2 SD»
по целям, а не фактическая граница всех кадров, не независимые
люди и не валидация классификатора. Из этих сводок нельзя вычислить
покадровую активацию на прошлом видео или проверить новые координаты.

## Что проверяет новый сценарий

Только геометрия уголков, без радужек, век, target/AOI или таймера,
допускает парный **уже вычисленный по глазам** прогноз в ограниченном
диапазоне той же камеры. Она не создаёт прогноз, не обучается
предсказывать экран, не поправляет координаты напрямую и не даёт
результат без обычного eye-patch. При расхождении двух глазных
предсказаний больше 16% диагонали остаётся обычный результат.
Строгая ветка сохраняет его классификацию «за экраном»; опциональная
ветка требует отдельно обученного Gradient All для возврата внутрь.
Обе — `raw` дополнения, не QC, не онлайн-адаптация и не коррекция AOI.

При двух сериях жёлтых точек оценивается разделимость по высоте:
пять сопоставимых пар, защитный зазор ≥ 1% высоты кадра между их
диапазонами, один фиксированный знак изменения. Если диапазоны не
разошлись, камера выключается **до красных точек**, выдаётся
`geometry_anchor_overlap`. Если красные точки расширили обычный
диапазон и он перекрыл второй, выдаётся `geometry_gate_unavailable`;
отбрасывать часть хороших кликов ради прохождения нельзя. В рабочий
предиктор положение головы не добавляется.

Синтетический v6: при умеренном совместном изменении нижняя ошибка
570→384 px на 144 общих экранных кадрах, без уменьшения количества
ложных вылетов; на обычном и далёком новом положении — точный fallback.
Отрицательный контроль: одна трансляция лица без помехи ухудшила
среднюю ошибку 30→41 px. Это причина не использовать положение лица
как самостоятельное доказательство наличия помехи и не переносить
результат в production без отдельной проверки. Ни реальные заэкранные
взгляды, ни дрейф внутри непрерывного интервала этим не измерены.

## Ручной прогон

`?models=nuisance-geometry&rev=20261110-143u` на localhost. Начать с
двух жёлтых серий: без кликов, смена положения только по подсказке,
немного и комфортно. Если видны красные — пройти обычные 25×2, затем
зелёные в трёх посадках; дополнительных ожиданий нет. Если тест
остановился, не повторять, сохранить техническую сводку.
`wecog-gaze-geometry-posture.v1-….json` содержит агрегаты и причины,
не видео, векторы или отдельные координаты. Никакой автоотправки.

Перед следующим шагом: проверить ранний допуск, нулевую/низкую
активацию при обычной посадке и после возврата и реальный парный
выигрыш при более низкой посадке. Не выбирать победителя только по
факту активации. Большую выборку и четырёхминутный тест пока не запускать.

Проверено: 129 целевых Node-тестов, 5 WebKit-сценариев на синтетике
(включая остановку до красных, перекрытие после красных и полный
прогон), typecheck, `git diff --check` и локальная ссылка `143u`.

## Результат реального прогона 143u

Один прогон Safari: 50/50 красных кликов, 6074 завершённых захвата,
без ошибок кадров; жёлтая проверка разделила 5/5 пар с защитным зазором
0,0945 высоты кадра. Средние радиальные ошибки на общих `raw` кадрах
для baseline / полного eye-patch / геометрического варианта: обычная
посадка 246 / 55 / 55 px; нижняя 268 / 118 / 112 px; после возврата
174 / 88 / 88 px. В нижней посадке на 275 общих кадрах: 257 смешанных
оценок, 18 сработавших защитных ограничений границы; дополнительное
подтверждение не вернуло внутрь экрана ни одного случая. Ложных вылетов
в этой серии не стало меньше. Выигрыш от смены самой модели заметнее
выигрыша от отдельного распознавания посадки. По одному пользователю
не меняем рабочий алгоритм; следующий локальный вопрос — сохраняется
ли выигрыш eye-patch в [непрерывном AOI-блоке](2026-11-10-issue143-continuous-aoi.md).
