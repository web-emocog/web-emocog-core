# Issue 143: сверка сессий 125/126 и исправление live QC

## Вывод

Файлы подтверждают неоднородную pre-block ошибку при пройденной общей validation.
Они также помогли воспроизвести дефект input live QC: отсутствие display-точки
скрывало accepted off-screen prediction в знаменателе on-screen доли. Этот путь
исправлен и версионирован. Это **не** доказательство устранения gaze drift.

Проверенные AOI-значения researcher export совпадают с расчётом по сохранённым
фиксациям participant export. Из этого не следует, что исходные фиксации точно
соответствуют реальному взгляду или что любая координатная ошибка исключена.

## Источники и пределы интерпретации

Пользователь предоставил два локальных participant JSON и соответствующие
researcher JSON из комментария issue #143. Содержимое прочитано read-only;
файлы/landmarks/покадровые ряды, идентификаторы аккаунта, invitation/token и
протокольные материалы не добавлялись в git или новые fixtures. Ниже только
derived числа. Исследовательские выгрузки содержат session IDs 125/126.

Пользователь не располагает сведениями о задании смотреть на конкретную сторону.
Поэтому попадание в левый/правый AOI и изменение медианы траектории нельзя
использовать как ground truth ошибки или как основание автоматической коррекции.
Контрольные validation targets известны, но выполнение инструкции взглядом
не проверено независимым eye tracker. Нет post-block known-target validation:
этими файлами нельзя измерить временной drift или момент его возникновения.

В metadata отсутствуют `gazeFeatureMethod` и `gazeCalibrationSampling`. Это
legacy/unknown provenance, а не подтверждение использования новой ветки.
Нет calibration feature rows/весов для воспроизводимого повторного fit; один
сохранённый precheck frame не заменяет калибровочную выборку. Новые модели v5
на этих файлах не обучались и не выбирались.

## Сверка AOI: что исключено, а что нет

1. Сопоставлены все 40 explicit presentation IDs каждой пары файлов.
2. Суммы stimulus records совпали с `gaze_analytics.presentations`:
   5362/5241 и 5968/5636 total/valid. Нельзя подменять их session-wide 16080/15268.
3. Для каждого presentation и каждого из двух AOI использованы сохранённые
   geometry/validity interval и `fixationInsideAoi()` канонической аналитики.
4. Повторно вычислены девять экспортируемых значений: dwell ms/%, gaze-on-target
   %, fixation count/median duration, revisit count, target reached/%, TTFF.
   Всего **720/720 совпадений в каждой сессии**, включая корректные null для
   отсутствующего события. Это сверка значений, не независимая научная валидация
   алгоритма фиксаций или всех UI/filter путей.

Следовательно, расхождение participant→researcher в проверенной AOI-арифметике
не обнаружено. Крупная ошибка прогноза может давать арифметически согласованные,
но научно ненадёжные AOI-значения. Уже добавленный `gaze_spatial_qc.v1` явно
отделяет availability от accuracy и не считает drift измеренным.

## Исправление live QC: `corrected_validity.v1`

До правки `handleGazeUpdate()` вызывал `addGazePoint(null)` при отсутствии
display X/Y. При наличии display передавались эти сглаженные координаты.
`QCMetrics` увеличивает gazeValid только для непустой точки и делит onScreen
на gazeValid. Таким образом, accepted off-screen prediction с display=null
исчезал из знаменателя onScreen. В другой негативной ситуации stale display
мог пройти в QC даже при `gaze.valid=false`.

Воспроизводящий browser test до исправления получил `{x:10,y:20}`, `null`,
`{x:10,y:20}` вместо corrected `{x:80,y:90}`, finite off-screen, `null`.

Теперь чистый `gaze-tracker/qc-signal.mjs`:

- требует явного `valid===true`, finite corrected X/Y и допустимый viewport;
- не использует raw/display/legacy aliases как запасной источник;
- возвращает finite off-screen point независимо от отсутствующего display;
- сохраняет explicit off-screen и проверяет corrected bounds;
- вызывается основным handler ровно один раз до display-ветки;
- не меняет predictor, display filter, AOI accumulator или gaze-series history.

Model gate rejection остаётся missing. Существующий pose/QC gate может
ужесточить решение, но голова не подставляется вместо gaze. On-screen процент
по-прежнему условен на accepted model signal: это не физический ground truth,
не доступность среди всех camera frames и не попадание в AOI.

Provenance `meta.tech.gazeQcSignalMethod: corrected_validity.v1` согласована в
producer, JSON Schema, TypeScript и server payload policy; другие значения
отвергаются. Поле опционально для legacy. Ни один новый исходный sample в typed
ingest не добавлен. Формулы score/долей и численные QC thresholds не изменены,
но источник наблюдений исправлен, поэтому значения могут отличаться. Старые
сессии не пересчитываются; tag не гарантирует однородность ранее накопленных
counters при восстановлении через обновление.

## Объём изменения, rollout и ограничения

Изменения находятся только в `feature/fix_issue_143`, без commit/push/deploy
на этом этапе. Новых ML-весов, зависимостей/датасетов или внешних сервисов нет;
лицензия собственного helper — лицензия репозитория. Нет DB migration, изменения
RBAC, invitation/session binding, backup/controller или API transport.

Проверяется канонический flow, не legacy `app.js`; старый файл не становится
новой точкой входа. Cache URL consumers обновлены согласованно. Не добавлены
калибровочные цели/скрытые паузы внутри 40 предъявлений. Ошибка QC по-прежнему
обрабатывается существующим lifecycle, не скрытой остановкой активной пробы.

Перед production — PR в develop, CI, review и real-camera/full-protocol приёмка.
Экспериментальные `axis_mixed`/`axis_auto` остаются explicit local opt-in и не
включены в published participant flow. Изменение QC нельзя выдавать за улучшение
accuracy модели. Rollback — обычный revert/release rollback; не удалять данные
и не ослаблять пороги. Исторические карты нельзя достоверно «исправить» по AOI.
