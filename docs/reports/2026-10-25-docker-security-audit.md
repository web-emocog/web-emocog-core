## Docker Verification

Docker Desktop is running. Testing used separate images
`wecog-api:security-audit-20261025` and
`wecog-web:security-audit-20261025`, not existing user images.
The disposable PostgreSQL 16.10 fixture used port 55439 bound only to loopback
and a separate internal Docker network. No user DB or persistent volume was
reused. The fixture is removed after the checks; Docker Desktop stays running.

Docker's desktop credential helper initially hung on public pulls. Builds used
a temporary public-registry-only Docker configuration under `/tmp`, with the
existing BuildKit plugin. User Docker credentials/configuration were not
modified or copied.

- Production API image: Node **22.23.4**, UID **10001**, dependency patch **7.3.2**.
- API smoke passes with a read-only root, dropped capabilities,
  `no-new-privileges`, bounded tmpfs and unavailable DB. `/health` remains live;
  `/ready` fails closed with 503 without PostgreSQL.
- Real Poppler produces three synthetic PDF pages at **1275 x 1650** pixels
  under the Linux resource wrapper. The exact-image release smoke passes.
- Real LibreOffice converts a synthetic two-slide PPTX under the same Linux
  limits, read-only root, dropped capabilities and **no network**.
- Web production smoke passes, including private-file exclusion and asset
  availability. Existing nginx log-redaction tests exercise actual HTTP requests.
- SHA-256 of the converter, lockfile, builder, analytics config, legacy shell
  and JSON-report code inside the images matches the current local source.
  Production images intentionally exclude tests. PostgreSQL tests/fixtures were
  mounted read-only; runtime modules/dependencies came from the built API image.

use actual image tools and explicit **test-only** auth/ingest limits (1000/min),

rejection tests remain in the full suite.

The PostgreSQL CI script now runs both security and protocol-persistence
suites, sequentially: one suite deliberately injects a DB trigger failure,
so concurrent execution could contaminate the other suite. CI settings and
their regression assertions were updated together.
