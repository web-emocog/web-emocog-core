# Issue #143: проверка модели по видимой части глаза

Ревизия диагностики: `20261109-143q` (первый прогон — `143p`). Новая модель подключена только на
localhost. Опубликованные протоколы, аналитика, QC-пороги и набор кандидатов
в авторизованной панели не изменены. Это не закрытие issue и не приёмка модели.

## Что проверяем

Нижние точки могут давать меньше устойчивых кадров при естественно прикрытом
веке. Общая задача — повысить точность относительно текущего
`same_eye_iris.v2`, в том числе при обычном движении головы, не принимая
положение головы за взгляд и не притягивая прогноз к стимулам.

`eye_masked_center.experimental.v1` берёт пиксели того же завершённого кадра,
что и остальные кандидаты. Уголки задают сетку, а верхнее и нижнее веки
приближённо ограничивают видимую часть. Координаты век не задают центр
и не входят в регрессию. Оценка центра максимизирует согласие контраста
внутри видимой области с тёмным шаблоном, с учётом площади ячейки и
сдвига освещения по строкам. Неоднозначное совпадение, недостаточная
видимость или отсутствие пикселей дают пропуск. Два глаза усредняются
до линейной регрессии X/Y, с прежним baseline iris/head gate.
Модели обучаются на общих пригодных кадрах красных точек; независимые
цели не используются для fit, а residual correction по-прежнему может
отклоняться независимой проверкой.

## Проверка с камерой

Первый реальный прогон (`143p`, Safari, камера 640×480) остановлен на
23-й точке через ~5 минут: 44 из 50 необходимых нажатий приняты за 162
попытки. Из 118 отклонений 117 — `eye_descriptors`, одно — `eye_signal`,
ни одного отклонения по позе. Рабочие контрольные дескрипторы доступны
на 8307/8312 (full) и 8290/8312 (Gradient All) завершённых кадрах; masked —
на 2581/8312. Это числа за весь запуск, не только за окна нажатий.
Ошибок захвата/предикторов не было. Поскольку прежний отчёт различал
только наличие дескриптора, установить точную причину отказа внутри
masked extractor по этому прогону нельзя. Ни точность, ни дрейф
на этом устройстве не измерены.

В `143q` нехватка признаков только для masked не заставляет повторять
точку. По 25 целям сохраняются агрегаты причин на пригодных кадрах двух
контрольных дескрипторов: недостаток видимых строк, слабый контраст,
слабое/неоднозначное совпадение, граница поиска или непригодная геометрия/
пиксели. Сбор использует те же два клика и те же eye/head thresholds.
Если хотя бы в одном принятом окне не хватило общих кадров для честного
сопоставления, после калибровки выдаётся технический JSON
(`masked_calibration_coverage`) и камера выключается без зелёных точек
и четырёхминутного ожидания. Неполная модель не обучается на более лёгких
целях. Изображения и покадровые данные не сохраняются.

При полном покрытии один локальный temporal run сравнивает baseline, полный eye-patch,
Gradient All и masked template. После калибровки и независимой проверки
коррекции — те же девять зелёных целей до и после четырёх минут без
контрольных точек и без адаптации. Можно моргать и двигаться естественно,
но не переставлять камеру и не менять окно/масштаб. Данные внутри
четырёхминутного интервала не считаются эталоном точности.

В отчёте `gaze_benchmark.v1` проверяются
`benchmark.modelSet=baseline_patch_gradient_masked.v1`, покрытие,
ошибка на общих кадрах, ложные вылеты на экранных целях и сдвиг по тем же
целям до/после. Отдельный ID/имя файла исключает смешение с прежней
серией. Если запуск прерван, сохраняется только техническая сводка;
это тоже полезный результат. Пиксели, координаты отдельных кадров и
веса не сохраняются и не экспортируются; запросов на API нет.
Результат `143p` не годится для продвижения кандидата на реальных кадрах.
Повторять прежний прогон или расширять выборку с этим кандидатом пока не нужно.

Разбор первого прогона: прежде всего доступность нижних целей и покрытие
общих кадров, затем средняя ошибка с равным весом целей и разница на общих
кадрах с каждым из трёх сравнений. До/после и raw/corrected остаются
раздельными. Отсутствие цели или уменьшение покрытия не считаются улучшением
точности; отсутствие провала в одном прогоне не доказывает устранение дрейфа.

Проверено в `143q`: 112 целевых Node-тестов, `npm run typecheck`,
`git diff --check` и три WebKit-сценария на синтетических кадрах.
Сценарий нехватки данных завершился за 50 нажатий: отдельная сводка
и выключение камеры, без ложной оценки точности. Полный локальный API-набор
в `143p`: 786 прошло, 5 пропущено.
