# Повторная проверка локального кандидата wecog

Проверка проведена на локальном кандидате `feature/signal-quality-profiles`.
Рабочие аккаунты, GitHub, продакшен и его данные не изменялись. Интеграционные
проверки использовали одноразовую PostgreSQL 16, локальный API и синтетические
стимулы. Реальные камера и микрофон не включались.

## Что исправлено

| Область | Исправление |
| --- | --- |
| Адреса стимулов | Загрузка использует конкретную публикацию и конкретный файл; префиксы `/api` и `/main/api` сохраняются. Подменённые адреса и перенаправления не используются, учётные cookies и referrer не отправляются. |
| Сохранение | Закрытая схема больше не отклоняет штатные поля промежуточного и финального пакета: числовой ID протокола, ID завершения, сводку PERCLOS, число результатов и события обрыва, повторов, трекинга и VPC. Сырые измерения и неизвестные вложенные поля по-прежнему запрещены. |
| Большие протоколы | Суммарный лимит повторов проверяется до разворачивания проб. Неподдерживаемый план не урезается молча и не запускается. Системная инструкция не занимает место в лимите измерительных блоков. |
| Резервный анализ | Незавершённый расчёт не дублируется. При остановке или смене протокола его поздний результат отбрасывается; ожидание не запускает дополнительные таймеры. |
| Участник | Пользовательская инструкция больше не обходит нажатие для перехода в полноэкранный режим. Демонстрационный сценарий входит в публичную сборку и не зависит от приватных файлов. |
| Аналитика | Для времени до первой фиксации отсутствие времени начала не считается рассчитанным значением. Наличие попадания в AOI и известная длительность по-прежнему отображаются. |
| Экспорт | Номер публикации за границей целых чисел PostgreSQL отклоняется как неверный запрос (400), а не приводит к 500. |

## Как проверяли

- `npm test` и `npm run test:rt-python` в `apps/api`, `npm run typecheck` в
  `apps/autotests`, отдельные тесты логики выпуска и аудит производственных npm-зависимостей.
- Миграции и `npm run test:postgres` на одноразовой БД. Проверены повторная
  доставка, права на экспорт и удаление, изменение состава проекта и запрет
  повторной загрузки после удаления сессии.
- Матрицы Chromium, Firefox и WebKit для воркеров и разрешений, аналитики,
  восстановления, сохранения физиологических интервалов. Регистрация также
  проверена в эмуляции iPhone. Публичная сборка проверена в Nginx, без доступа
  к внутренним исходникам и документам.
- `LIVE_STIMULUS_FIXTURE` с отдельным API: реальные загрузки изображений и
  видео, библиотека, права владельца/коллеги/другого проекта, показ участнику,
  RT, приём сформированного участником пакета и наложение карты/AOI на ту же
  публикацию. Проверены ширины 390 и 1280 px и полноэкранный вариант.
  `scripts/seed-live-stimulus-fixture.cjs` генерирует отдельные тестовые
  учётные записи; файл с ними хранится приватно и удаляется после прогона.
- Реальный браузерный обрыв: сохранение до остановки, завершение без сети,
  перезагрузка, потерянный ответ после успешной записи и стабильная ссылка
  после второй публикации. Проверялись неизменность отправленного пакета,
  один засчитанный запуск и связь с публикацией без хранения bearer-кода
  приглашения в JSON результата.
- Добавлена обязательная конфигурация `playwright.session-live.config.ts`:
  обычное завершение RT и опроса, невалидная попытка и успешный повтор,
  промежуточное сохранение, перезагрузка, обрыв сети и потерянный ответ
  сервера. Она отказывается запускаться без явно указанной одноразовой БД.
  Эти проверки включены в PostgreSQL release gate для Chromium и Firefox.
  Локально также выполнен WebKit; удалённый GitHub Actions пока не запускался.

Ускоренный синтетический контроль длительностей 40 и 125 минут также выполнен.
При одинаковых временных метках и кадрах воспроизведение под нагрузкой сохраняет
результаты ЧСС/дыхания и интервалы покрытия. Контроль с пропуском кадров
намеренно отличается: он не выдаётся за непрерывное наблюдение.

## Совместимость

В этой повторной проверке новые миграции не добавлялись. Схема
`session_feature.v1` дополнена явно типизированными штатными событиями, а не
разрешением произвольного JSON. Исторические массивы результатов остаются
допустимыми наряду со счётчиком; описание попытки и краткий список повторов
сохраняют отдельные закрытые структуры. Измерительные пороги и веса моделей
не менялись.

Для последующего выпуска API и интерфейс нужно проверять как один кандидат.
Откат только схемы API при сохранении браузера, формирующего штатные поля,
вернёт отказ 422. Результаты и миграции не удалять: при ошибке выпуска
восстанавливается прежний согласованный образ приложения. Фактический выпуск
и проверки GitHub Actions в рамках этой локальной работы не выполнялись.

## Нагрузка

Один парный прогон на движок: одинаковая локальная запись MCD-rPPG, профиль
v2 без модели корпуса, 20 с разогрева и 10 с измерения. Сравнение с ранее
зафиксированным v2 до переиспользования кадров, не с сервером. Первый пробный
прогон с 8 с разогрева остановился на сборе нейтральной настройки и не включён
в таблицу. Правила калибровки не смягчались.

| Движок | FPS ранее | FPS сейчас | FPS доставки в кандидате | Задержка таймера UI p95 |
| --- | ---: | ---: | ---: | ---: |
| Chromium | 24.59 | 25.07 | 25.07 | 4.5 мс |
| Firefox | 21.09 | 21.59 | 21.69 | 10 мс |
| WebKit | 29.30 | 29.39 | 29.29 | 5 мс |

Ошибок расчёта в завершённых прогонах не было. Разницы одного прогона
недостаточно, чтобы заявить прирост. Частота в Firefox в этом опыте была
ограничена скоростью поступления кадров тестового потока; это не диагноз
реальных камер и драйверов.

## Что остаётся подтвердить

- [Приёмку на реальных устройствах](../operations/real-device-acceptance.md):
  проблемные камеры и браузеры, длительное прохождение, восстановление после
  реального обрыва и фактическая частота кадров.
- Научную точность взгляда, ЧСС, дыхания и мимики по синхронной эталонной
  записи. Синтетический тест или повтор видео проверяет программу, а не
  точность измерения показателя у человека.
- Условия фактического выпуска: настройки инфраструктуры, доставку почты,
  квоты и нагрузку открытого сервиса. Локальный прогон не подтверждает
  продакшен и не заменяет приёмку.
