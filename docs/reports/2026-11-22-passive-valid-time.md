# #177: добор пригодного времени и длинные пассивные пробы

## Выпуск и границы

PR #178 слит в develop обычным merge `3dfe70582f8d178ec1ed8bc340bd40fe6b34a320`.
Он исправляет три замечания к #183; #183 не слит в main. Защита веток/проверки
не обходились, чужие коммиты не откатывались и история не переписывалась.
Данная работа выпускается отдельным feature PR в develop, без автоматического
слияния или закрытия #177 до человеческой приёмки.

## Реализация

- RU/EN-настройка пассивного блока, выключена по умолчанию; предел продления
  не больше +50%, непрерывный засчитываемый участок от 1 с. Исходное условие,
  RT и обычные опубликованные протоколы не меняются.
- Preflight, публикация и приглашение проверяют статичность закреплённого
  файла. RT, видео, аудио, ручная смена и неподтверждённая анимация запрещены.
- Целое монотонное разбиение всего показа: принятое время, исключения и причины,
  цель, фактическое время, deadline, продление и достижение предела. Никакой
  интерполяции после последнего кадра. Переполнение детализации даёт незачёт.
- Во время пробы нет новых индикаторов, всплывающих QC-подсказок и скрытой паузы.
  При недоборе действует прежний ограниченный повтор только повреждённых проб.
- Первый короткий пригодный участок не попадает в gaze-накопители до 1 с;
  разрывы разрывают фиксации. Timestamp захвата не заменяется временем inference.
  Неизвестная видимость областей лица не даёт принятого времени.
- При разрыве очищается только рабочее окно физиологии; принятая история не
  стирается. Новый вывод требует полного свежего окна 10/20 с. Совместимость
  методов и опубликованные scientific/QC thresholds сохранены.
- Незавершённая попытка уже есть в checkpoint, с `qualityValid:false`; reload
  не делает её успешной и не переносит время в новый показ.
- API проверяет partition, суммы, опубликованный opt-in, исходный стимул/цель
  и границы доступных фиксаций. Удаление `validTime` из новой записи отвергается.
- Аналитика, AOI/heatmap, extended features, JSON/CSV и карточки попыток сохраняют
  actual/accepted отдельно; не строят переходы через разрыв и не выдумывают
  недостающие фиксации. Для старых записей без opt-in поведение прежнее.

## Нагрузка на длинном просмотре

Подтверждена растущая работа: резервная копия клонировала накопленные eye
series и повторно считала перекрывающиеся attention scopes. Активная серверная
копия теперь явно ограничена текущими сводками; полные ряды остаются в локальных
delta chunks и финальном расчёте. Старые attention/blink/perclos не выдаются
за актуальные. No-change gaze checkpoint не пересматривает весь retained buffer.
Правила опубликованного QC подготавливаются один раз, не проверяют список
статичных файлов на каждом кадре.

Это не сокращение измерительных samples/частоты и не снижение QC-порогов.
Сырые видео/аудио не добавлены. Eye-signal история не обрезается произвольно;
многочасовая память остаётся отдельным acceptance gate.

Со слов исследовательницы: MateBook 16 D, Windows 11 Home 25H2, i5-12450H,
16 ГБ RAM, встроенная камера; Chrome 155.0.8059.85 и Edge. На просмотре
3/5 минут наблюдалось снижение с 29 до 16 FPS. Диагностический пакет этой
попытки пока не предоставлен. Эти слова не устанавливают частоту камеры
против частоты анализа и не являются результатом замера исправленной версии.
На этом устройстве исправление FPS ещё не подтверждено.

## Данные, безопасность и обратная совместимость

Additive optional field в закрытой session schema и TypeScript; новых таблиц,
миграций или endpoint нет. Server admission, tenant tuple, CSRF, membership,
private-media и checksum-проверки сохранены. Неизвестное качество остаётся
неизвестным, а не успешным нулём. Пределы request/transport не увеличены.

Дополнительная сквозная проверка с настоящими HTTP/БД выявила два пропуска
закрытой схемы: `experimentMeta.backupScope` активной копии и
`cognitiveResults[].invalidationReason` после reload. Схема/типы разрешают
только существующие литералы `light_summary_without_signal_series` и
`page_reloaded`, не произвольные строки или новые поля. Проверка проходит
путь от частичной серверной копии через reload к новой попытке и финальному
ingest; физическая камера в этом тесте запрещена, качество задаёт тестовый
источник. Это проверка сохранности/жизненного цикла, не измерение FPS.

Обновлены browser query versions до `20261122-validtime1`, включая родителей
и HTML. В manifest добавлены только два общих runtime helper, всего 296 файлов.
Тесты с warm HTTP cache проверяют реальное обновление, без routing cache bypass.

## Ручная приёмка

1. Создать новую публикацию: пассивный блок с одной статичной встроенной
   картинкой 180 с; включить «Добирать валидное время», предел +50%.
2. При двух коротких нарушениях убедиться, что картинка не меняется и не
   перекрывается подсказкой; при наборе 180 с пригодного времени нет повтора.
3. При длительном 16 FPS ниже опубликованных 25 добиться предела 270 с:
   незачёт и объяснение, а не успешное прохождение.
4. Проверить JSON/CSV и карточку: target, accepted, actual, excluded intervals
   и причины. Gaze/AOI не соединяют разрывы; физиология заново прогревается.
5. Перезагрузить активную пробу: предыдущий показ исключён, новый начинает
   время заново; ранее принятые пробы сохраняются.
6. Повторить 3- и 5-минутный тест на указанном ноутбуке от сети, с тем же
   протоколом/каналами в Chrome и Edge. Сохранить diagnostics первых/последних
   30 с, camera/analysis FPS, stage timing и отметки backup; не выдавать
   синтетический replay за проверку производительности камеры.

## Rollout / rollback

Сначала совместимые API и frontend, затем новая публикация с явным opt-in;
существующие приглашения не мигрируются. Для отключения создать новую
публикацию без опции, не менять задним числом уже принятые данные. Не откатывать
validator на сервер, который больше не понимает сохранённое поле; до полного
отката оставить additive schema/read/export поддержку. Main обновляет
пользователь после CI и приёмки develop.

Точные результаты автоматических прогонов фиксируются в описании feature PR.
Зелёные автотесты не заменяют Windows/real-device и scientific acceptance.
