## Новые Исправления

1. **GPU-маски MediaPipe.** Новый `MaskReader` читает публичную WebGL texture
   через RGBA/FLOAT, обходя несовместимый RED/FLOAT readback Firefox и проверку
   отсутствующего `self.document` в Mac Worker. Vendor, модель и scientific/QC
   thresholds не менялись. Сохранено точное float32-to-Uint8 преобразование
   закреплённой версии; GL framebuffer/PBO/pack state восстанавливаются и при
   ошибке. Scratch buffers переиспользуются, память ограничена, framebuffer
   освобождается. GPU failure имеет однократный CPU retry внутри Worker с
   прежним capture timestamp и явной диагностикой.
2. **Границы маски.** Padded bbox лица ограничен изображением; confidence и
   региональные landmark samples больше не переходят в соседнюю строку при
   x<0/x>=width. Такие обращения могли читать совершенно другой участок.
   Пороговые значения и правила приёмки не ослаблены.
3. **Согласие и старый invitation runner.** Deadline 15 секунд охватывает
   заголовки и тело ответа. Зависший документ не оставляет бесконечный pending
   и не создаёт подпись. SHA-256 успешного документа не меняется. #47 и #58.
4. **Старый ProtocolRunner.** Найдена attribute injection через `field.name`
   и границы scale. Кавычки экранируются, числа проверяются; текст и имена
   ответов сохраняются, включая `__proto__`/`constructor` без изменения
   prototype; HTML не исполняется. #45.

Основание совместимого readback: официальный
[MediaPipe issue #5879](https://github.com/google-ai-edge/mediapipe/issues/5879).
Сообщение upstream само по себе не доказывает исправление нашего кода:
основание принятия — локальные тесты и повторные измерения ниже.

## FPS: Что Доказано И Что Ещё Не Исправлено

Приватный hash-locked MCD clip: 60 секунд, 640×480, около 29,9 video FPS,
real-time playback. Face/eyes/rPPG/FACS/segmentation/pose, без камеры/микрофона,
передачи данных и пользовательских аккаунтов. Замеры по одному движку;
Chromium run2 частично пересёкся с окончанием synthetic suite и исключён из
контрольного вывода, использован чистый run3.

| Движок | Анализ FPS | Segmentation mean | Delegate | Строгий FPS-критерий |
| --- | ---: | ---: | --- | --- |
| Chromium 143, чистый run3 | 24,38 | 157,9 мс | CPU Worker | Не пройден |
| Firefox 144, run1/run2 | 22,06 / 21,97 | 23,0 / 22,6 мс | GPU Worker | Не пройден |
| WebKit 26, run1 | 29,88 | 23,1 мс | GPU Worker | Пройден |

В предыдущем CPU-замере Firefox сегментация занимала около 4307 мс, иногда
упиралась в deadline и уходила на main thread. Теперь этот bottleneck устранён
на проверенном клипе, но общий FPS Firefox не вылечен. Точная разбивка:
копирование пикселей ≈0,28 мс, face inference ≈43,3 мс, derived features ≈0,09 мс.
В чистом Chromium inference ≈39,1 мс, pixels ≈0,34 мс, derived ≈0,06 мс.
Значит, продолжать только оптимизацию canvas недостаточно.

Эксперимент GPU-сегментации во всех движках **отклонён для Chromium/Mac**:
анализ упал примерно до 6,48 FPS, segmentation выросла до 382,9 мс. Поэтому
сохранён измеренный CPU-путь Chromium/Mac; Firefox/WebKit используют совместимый
GPU readback. Политика и фактический fallback отражаются в `tech.framePipeline`.

Профилирование выполняется только loopback replay harness: first-party source
инструментируется для измерений, production face source не изменяется.
Диагностический файл `profile-stages.mjs` отказывается работать с неизвестной
версией source. Raw face не попадает в Git или отчёты.

Критерий не понижен ради зелёного результата: analysis >=25 FPS, UI timer
p95<=10 мс, capture gaps<=250 мс, отсутствие 3 секунд подряд ниже 25,
Workers без fallback на UI и segmentation mean<=1000 мс. Наличие Worker,
плавное видео или прохождение unit-теста не заменяют этот критерий.

**Универсальная проблема FPS остаётся открытой.** Эти движки Playwright —
не доказательство поведения установленных Safari/Chrome/Firefox с настоящей
камерой. Персональная gaze calibration, настоящий RT input, полный protocol UI
и длительное сохранение не входят в этот clip benchmark. ЧСС/дыхание/взгляд
не объявлены научно валидированными: MCD clock/reference alignment и влияние
нагрузки на физиологические оценки требуют отдельной проверки.
