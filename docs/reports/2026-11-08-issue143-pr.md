# Заголовок PR

Gaze calibration fixes and developer model benchmark (#143)

# Текст PR

## Назначение

Related to #143. Исправления геометрии gaze, сбора калибровочных кадров и
пространственного QC, а также отдельная диагностика для сравнения кандидатов
на разных людях/устройствах. PR **не закрывает issue #143**: универсальное
улучшение точности и устранение длительного дрейфа ещё не приняты.

Целевая ветка: `develop`. Перенос в `main` и production-деплой — отдельно,
после review и CI.

## Общий gaze / calibration / QC

- Исправлено соответствие радужек контурам того же анатомического глаза и
  направление вектора head roll; добавлена provenance `same_eye_iris.v2`.
- Закрытые глаза исключены из калибровочного fit/average. Общий
  `click_capture.v1`: 25 целей × 2 отдельных клика, свежие уникальные captures
  после клика; stale/duplicate/blink/pose-rejected кадры не обучают модель.
  Исходные требования к usable frames и gates не снижаются при повторе клика.
- Общие correction/independent-benchmark функции используются основным flow
  и диагностикой. Uniform X/Y offset сохраняет LOOCV/independent rollback;
  нет принудительного применения поправки из-за одной большой absolute error.
- QC использует unsmoothed valid corrected gaze, не display/raw aliases.
  Доступность/confidence отделены от пространственного качества. Явный
  сохранённый провал validation не публикует достоверные AOI-числа; legacy
  отсутствие validation не превращается в выдуманный fail/pass или нули.
- Обновлены analytics/export caveats, контракты, schema/TypeScript, provenance
  и cache tags связанных browser consumers. Новых SQL-миграций нет.

## Отдельный developer benchmark

- Новая карточка **«Сравнение моделей взгляда»** в панели разработчика;
  документ `/apps/participant-web/tools/gaze-benchmark.html`.
- Только `admin/developer`: обычный cookie auth, свежий `/auth/me` перед
  камерой, блокировка/очистка при смене аккаунта, проверка Permissions-Policy.
  Новых ролей, публичного bypass, tenant access или server write endpoint нет.
- Четыре регрессии на одном завершённом camera/analyzer frame: baseline,
  full eye-patch, Gradient All, horizontal black top-hat. Общий subset
  calibration captures; fit/regularization только на калибровке. Raw и
  corrected сравниваются раздельно; common-frame deltas отдельно от marginal
  средних при разных accepted subsets.
- Три versioned программы: `spatial.v1`, `posture.v1` (A–B–A) и
  `temporal.v1` (одинаковые цели до/после четырёх минут без целей).
- Модели заморожены между контрольными сериями. Нет target/AOI attraction,
  адаптации по времени, head→target fit или остановок внутри опубликованного
  непрерывного исследовательского блока.
- Экспериментальные descriptors доступны только explicit opt-in диагностике;
  published participant flow их не включает, ingest/schema отвергают эти tags.
- Выгрузка `gaze_benchmark.v1`: метрики ошибок/bias/spread/missingness,
  gate/availability/cadence counts, CV/correction decisions, раздельные timings,
  coarse browser/OS/viewport/camera и completed/failure status. Есть безопасные
  сводки незавершённых запусков без выдуманной accuracy.
- Нет видео/аудио, изображений глаз, landmarks, feature vectors, weights,
  сырых gaze-рядов или account identifiers в JSON. Результаты не отправляются
  автоматически и не записываются в IndexedDB/localStorage.
- Один sensor owner; explicit consent/Start, bounded initialization/imports,
  Stop/Esc/hidden/pagehide/viewport/camera teardown, закрытие late streams,
  сериализация native model init. Нет canvas trail от перемещения точки.
- Localhost harness переиспользует тот же controller/factory/summary. Assets
  diagnostics не зависят от `apps/autotests`, исключённого из production image.

## Научные ограничения и собранные наблюдения

Human v7–v10 и результаты сессий 125/126 разобраны в мини-отчётах; исходные
персональные JSON, видео, pixels и покадровые features в git не добавлены.
Ни один экспериментальный кандидат не признан универсальным победителем.
Top-hat не решает подтверждённо ошибки у нижних целей, а стабильная средняя
ошибка не означает отсутствие signed drift. Offline quadratic mapping и
within-click covariance loss сохранены как exploration/negative evidence,
а не подключены как production-улучшение.

Тест является standalone gaze-диагностикой, не полным multimodal протоколом.
Head diagnostics — proxies, не измеренная физическая поза. Точность внутри
четырёхминутного интервала неизвестна; off-screen specificity этим human
протоколом не измеряется. Нужны расширенная real-device выборка и независимая
приёмка до выбора/продвижения кандидата и закрытия issue.

## Проверки

Перед этим push повторно выполнено локально (это не результат GitHub CI):

- Полный API suite (Node 24, serial): **783 tests, 778 passed, 0 failed, 5 skipped**.
- Developer access/lifecycle/layout, Chromium/Firefox/WebKit: **36 passed**.
- Typecheck и `git diff --check`: passed.

Ранее выполненные полные synthetic clock replays трёх программ, дополнительные
issue143/duplicate-ownership regressions и ручные real-device наблюдения подробно
описаны в технических мини-отчётах. Их числа не выдаются здесь за новый прогон.

В ходе разработки наблюдался существующий 5000 ms timeout fake Docker startup
fixture при параллельной нагрузке; в текущем полном serial-прогоне он не
воспроизвёлся. Fixture и его deadline не менялись. Для длинного functional clock replay увеличен только harness
wall-time, без пропуска 33 ms callbacks или ослабления scientific/FPS gates.

Отдельная PostgreSQL integration DB, Linux/container web-image smoke и большая
real-device/scientific приёмка в этих результатах не заявляются.

## Rollout и тестировщики

После успешного переноса в `main` и штатного деплоя карточка появится в developer
panel. На этапе пилота используются только существующие admin/developer accounts.
Ручной rollout БД, выдача новых ролей или ослабление nginx policy для этой
диагностики не нужны.

Каждый полный комплект — три JSON на одном устройстве/браузере. Тип программы
сохранён в имени файла и `benchmark.protocol`. Общего participant/series ID
между запусками пока нет: организатор выдаёт короткий код и принимает комплект
одним сообщением, не публикуя ФИО/email. Неудачные запуски тоже собираются.
