# Старый аудит: диагностика и уведомления моделей

Локальный кандидат `feature/signal-quality-profiles`, 7 ноября 2026 года.
GitHub, production и исходная таблица Google Sheets не изменялись. Физические
камера и микрофон не включались; новые тесты используют искусственные ошибки,
модельные заглушки и настоящие Workers без захвата человека.

Закрыты строки **44, 158, 171, 174, 178**. Из исходных 239 строк теперь
**115 исправлены**, 62 неактуальны/не подтверждены, **62 остаются**, включая
два частичных пункта. Это подсчёт строк аудита, не независимых ошибок.

## Исправления

| Строка | Исправление |
| --- | --- |
| 44 | GazeTracker больше не возвращает false из-за исключения уведомления после уже успешного расчёта. Синхронный сбой и отклонённый Promise onCalibrationComplete не меняют готовность, коэффициенты и предсказания. Реальные ошибки расчёта по-прежнему дают false. |
| 158 | FaceSegmenter не пишет исходное исключение сегментации в прямую консоль или error-result. Возвращается фиксированный технический код. После окончательной ошибки инициализации frame-вызовы не загружают модель снова и снова; явный initialize/reset разрешает повтор. Маски освобождаются и при ошибке. |
| 171 | Ошибка калибровки диагностируется фиксированным ограниченным кодом без исключения с данными. Для готовности используется результат calibrate/isCalibrated, а не успешность необязательного наблюдателя. |
| 174 | Исключение onInitialized больше не принимается за отказ Worker с переходом к второй модели в основном потоке. Изолированы также асинхронные отклонения и onError. Сохраняются контекст this и исходные аргументы callback. Автоматическая диагностика класса не выводит исходные исключения. |
| 178 | Прямые логи QCMetrics заменены необязательной диагностикой. Сводки для логов строятся только при включённом приёмнике; передаются типизированные счётчики, не координаты. Ошибка приёмника не влияет на расчёт QC или остановку. |

Общий helper `participant-diagnostic.mjs` изолирует уведомления и ограничивает
повторные ошибки через WeakMap экземпляров. При выключенной диагностике
ошибки не накапливаются в этом реестре; при включённой один и тот же код
записывается один раз до reset, даже если сам приёмник выбрасывает исключение.
Синхронное уведомление не создаёт дополнительный Promise; асинхронное
наблюдается с обработкой отклонения, без ожидания в критическом пути модели.

На 100 вызовов после окончательного сбоя в стенде выполнялась одна цепочка
попыток GPU → CPU, а не повторная инициализация на каждом кадре. После reset
и восстановления фабрики модель снова успешно запускается.
Нормальный stopPreCheck очищает ошибочное состояние сегментатора, но при
работающем общем pipeline не сбрасывает его модель. Готовая модель при
обычном reset сохраняется, повторной загрузки весов не добавлено.

Примеры README для моделей переведены на локальные закреплённые ресурсы и
явный await initialize вместо CDN/latest и прямого вывода исключения.
Это не новая версия модели: веса и численные параметры не менялись.

## Данные И Границы

- Не менялись алгоритмы, веса, делегаты CPU/GPU, численные пороги QC,
  частоты каналов, формат успешного предсказания и capture clocks.
- Нет новых API endpoints, миграций БД или полей биометрических измерений.
  Сегментация на ошибке выдаёт фиксированный segment_inference_failed /
  segment_model_unavailable с прежними признаками технической недоступности.
- Исходный Error по-прежнему передаётся в пользовательский onError для
  совместимости. Сам callback может намеренно писать его куда-либо: это
  не изоляция произвольного пользовательского JS и не обещание полной
  анонимизации всех диагностических каналов.
- Классические запасные обёртки с собственными логами остаются отдельными
  открытыми строками 156, 162, 172, 176; этот проход их не закрывает.
- Исторические JSON и уже сохранённые журналы этим исправлением не
  переписываются и не анонимизируются.
- Согласованы URL HTML/wrapper/index/class/helper/Worker на
  `20261107-7`. Helper и GazeTracker/QCMetrics нельзя частично обновлять
  поверх старых кешированных экспортов.

## Проверки

- Полный API/Node набор: **899 прошли, 8 условных пропусков, 0 ошибок**.
  PostgreSQL-интеграции этим запуском не подтверждаются.
- Общий браузерный набор: **396 прошли, 33 пропуска, 0 ошибок** в Chromium,
  Firefox и WebKit. Пропуски требуют отдельного настоящего API/БД/стимулов.
- Workers/модели/session-runtime: **264/264**, обработка кадров и отсутствие
  дублей: **84/84**, оба набора в трёх движках.
- **12 новых браузерных проверок** реальных face/segment Workers с
  синхронным и асинхронным отказом onInitialized: готовность true,
  backend worker, один Worker, отсутствие main fallback и unhandled
  rejection. После dispose Worker закрыт.
- **3 новые браузерные проверки** QC: полные сводки и счётчики в точности
  совпадают при выключенной, включённой и падающей диагностике. Время
  контролируется тестом; координаты в диагностические отчёты не попадают.
- Node-проверки подтверждают неизменность коэффициентов, нормировок,
  координат, validity/confidence взгляда при отказе уведомления.
  Проверены main/Worker initialization, сохранение this/аргументов,
  отклонённые Promise и бросающий getter then.
- На 1000 одинаковых ошибках приёмник вызывается один раз, в том числе
  при собственном исключении приёмника. Reset разрешает следующий отчёт.
  На 100 ошибках чтения масок закрыты все 200 масок; результат и события
  не содержат синтетический приватный текст исключения.
- TypeScript, синтаксис изменённых JS, статический release-audit и
  git diff --check прошли.
- Собран `wecog-web:old-audit-models-1107`, **260 разрешённых файлов**.
  Отдельный read-only контейнер прошёл HTTP smoke, проверку MIME модулей,
  согласованных версий и nginx -t; тесты/API/служебные файлы не доступны.
  Контейнер после проверки удалён.

В первом API-прогоне обновление browser query-tag затронуло CommonJS require
в изолированном тестовом стенде. Исправлен только Node-путь: браузерные
версии сохранены. После этого весь набор прошёл без исключения тестов и
ослабления проверок качества.

## Ограничения И Выпуск

Это техническая проверка, не новая оценка научной точности или фактического
FPS на живой камере. Не проводились новые длительные записи и production
проверка; #132/#144/#146 не закрываются этим проходом целиком.

После согласования выпускать единый веб-образ. Уже открытый эксперимент не
следует принудительно перезагружать во время измерения ради обновления.
Откат — предыдущий согласованный веб-образ; API, БД и контрольные точки
миграции не требуют.
