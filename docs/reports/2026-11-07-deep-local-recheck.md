# Глубокая повторная локальная проверка

Проверяется текущий незакоммиченный кандидат `feature/signal-quality-profiles`,
включая накопленные изменения безопасности, регистрации, квот, стимулов,
сохранения и аналитики. Проверки не обращались к production. Использованы
одноразовая PostgreSQL 16, локальные API, синтетические учётные записи и медиа.
Физические камера/микрофон не включались. Push, PR и деплой не выполнялись.

## Найдено и исправлено

| № | Ошибка | Исправление и защита от регрессии |
| --- | --- | --- |
| 1 | `datasetSha256` вычислялась до добавления selection | Выборка входит в пакет до хеширования и проверки лимита; unit и реальный HTTP-экспорт сверяют сумму. CSV сохраняет тот же манифест. |
| 2 | Отсутствующий lifecycle выдавался за подтверждённое незавершение | Legacy/неизвестный статус даёт null и явную причину, не false. |
| 3 | Завершённый Test Hub формировал не принимаемый API completedAt | Добавлено ограниченное поле времени в закрытую схему; проверен настоящий pushHubRun → агрегатор → валидатор. |
| 4 | Скрытый таймер приводил к 422 | Явно описаны name/startsAt/hidden/finishedAt и имя в completion event, а также строковый ID в событии запуска. Полный RT+опрос со скрытым таймером проходит ingest в трёх движках. Неизвестные поля по-прежнему запрещены. |
| 5 | Снимок мог создаться после удаления сессии и сохранить ссылку на неё | Кандидаты блокируются FOR SHARE OF s до COMMIT; реальный конкурентный тест проверяет ожидание удаления и отсутствие оставшегося снимка. SQL-конфликты переводятся в 409. |
| 6 | Audio требовал место для poster, которого не создаёт | Headroom poster равен нулю только для audio. Проверки квоты, диска, путей и полного декодирования сохранены; 12 отдельных регрессий. |

| 8 | Отказ checkpoint перед следующей пробой оставлял блок активным и блокировал finish | Явное аварийное завершение с interrupted presentation и protocolTermination; прошлые принятые ответы доставляются. Проверен отказ после первого ответа на реальном API в трёх движках. |

| 10 | Fallback после primary revision 7 терял revision и не мог очистить подтверждённую сессию | Сохраняется primaryRevision. Неизменённый primary очищается; конкурентный revision 8 и неизвестный legacy fence защищены. |
| 11 | Группа присваивала смеси методов версию первой сессии | Provenance собирается по вошедшим измерениям; смесь помечается mixed_versions с детерминированным хешем методов. Значения и веса участников не изменены. |
| 12 | Метод ЧСС/дыхания терялся на уровне минуты/попытки | Опциональный methodVersion передаётся collector → interval → checkpoint → API/таблица/экспорт. Новые, старые и смешанные интервалы различаются; версия формата не выдаётся за метод измерения. |
| 13 | В независимой выгрузке RT-окон терялось сохранённое условие | condition_id сохраняется и проверяется в JSON/CSV. |

## Границы изменений

Измерительные пороги, веса моделей, правила допуска кадров и расписание
инференса не ослаблялись. Интервальная версия метода — метаданные, не новое
обучение или независимая научная валидация. Браузерные версии ресурсов обновлены
согласованно, без второго экземпляра циклически импортируемого runtime.

В физиологическом контракте добавлено необязательное ограниченное поле
methodVersion. Существующие интервалы принимаются без него; произвольные
вложенные поля не разрешены. Изменения БД не требуются. Старые данные не
пересчитываются. Исходные роли, принадлежность к проекту и права на приватные
стимулы не расширены. Реальные биометрические записи не добавлены в репозиторий.

## Что остаётся внешней приёмкой

- Проблемные реальные устройства, длительная физическая камера, сон ОС и
  длительная работа с другими приложениями. Headless WebKit не заменяет
  установленный Safari.
- Точность взгляда, ЧСС, дыхания и мимики против синхронных эталонов. Влияние
  яркости стимулов на дыхание не устранено численным уточнением спектрального
  пика. Различие причин отказа ЧСС Safari/Chrome требует обещанных diagnostics.
- Реальный SMTP/DNS, эксплуатационная нагрузка и независимая security/legal
  приёмка открытой регистрации. Локальная почта и синтетический тест не
  доказывают доставку писем на production.
- Старый fallback без известной primary revision намеренно не получает права
  удалять существующий primary. При таком конфликте нужно сохранить выгрузку
  и восстановить данные явно, не подменять fence текущей ревизией автоматически.

## Последующий выпуск

API и frontend выпускать согласованным кандидатом: старый закрытый API может
отвергнуть новые штатные поля таймеров и methodVersion. Перед выпуском нужны
согласованный DB/uploads backup, GitHub CI и человеческое ревью. Откат — на
предыдущую согласованную пару образов; не удалять данные или миграции ради
отката интерфейса. Абсолютное отсутствие багов этой проверкой не гарантируется.
