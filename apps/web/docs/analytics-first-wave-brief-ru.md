# Аналитика Emocog: первая волна

**Краткий документ для согласования с научным руководителем**  
**Цель:** к началу исследований получить работающую аналитику реальных сессий и групп без демонстрационных значений.

## 1. Что должно войти в первую волну

Предлагаются четыре раздела:

1. **Сессия** — результаты одного участника.
2. **AOI и heatmap** — показатели внимания по stimulus и областям интереса.
3. **Группа** — сводка и сравнение участников/условий.
4. **Качество данных** — QC, confidence и причины исключения.

Все показатели рассчитываются только из реальных session data. Если данных нет, интерфейс показывает «Нет данных», а не `0` и не demo-значение.

## 2. Метрики одной сессии

### AOI и взгляд

| Метрика | Что показывает |
|---|---|
| **Heatmap** | Распределение взгляда на конкретном stimulus |
| **Gaze-on-target, %** | Доля валидного времени взгляда внутри целевых AOI |
| **Dwell time, ms и %** | Общее время внимания к каждой AOI |
| **Fixation count** | Количество фиксаций в AOI |
| **Median fixation duration, ms** | Типичная длительность фиксации в AOI |
| **Time to first fixation, ms** | Через сколько времени участник впервые зафиксировался на AOI |
| **Visits / revisits** | Число посещений AOI и повторных возвращений к ней |
| **Target reached** | Была ли хотя бы одна валидная фиксация на целевой AOI |

Результаты показываются по схеме:

```text
Session → block/task → stimulus → AOI
```

Тренировка и основная часть анализируются отдельно, даже если используют один stimulus.

### Выполнение задачи

Для задач, где есть ответы участника:

- accuracy, %;
- reaction time: медиана и среднее;
- количество правильных и ошибочных ответов;
- omissions — пропущенные ответы;
- commissions — ответы там, где отвечать не требовалось;
- число завершённых и исключённых trials.

Эти показатели показываются только для подходящих типов задач.

### Качество данных

Рядом с результатами всегда отображаются:

- QC class и QC score;
- число всех и валидных gaze-сэмплов;
- valid gaze, %;
- low confidence, %;
- off-screen, %;
- время взгляда вне stimulus;
- число валидных и исключённых trials;
- версия алгоритма расчёта.

## 3. Групповая аналитика

Групповая вкладка нужна уже в первой волне, но сначала как прозрачная описательная статистика без автоматических научных выводов.

### Состав выборки

- общее число сессий и участников;
- число включённых и исключённых по QC;
- распределение VALID / BORDERLINE / INVALID;
- число валидных наблюдений для каждой метрики;
- причины исключения данных.

### Сводка по метрикам

Для dwell time, fixation count/duration, TTFF, revisits, gaze-on-target, accuracy и reaction time:

- `N` валидных участников;
- медиана и межквартильный размах — основные значения;
- среднее и стандартное отклонение — дополнительные значения и export;
- минимум и максимум;
- 95% confidence interval, если он корректно применим к выбранной агрегации.

Участник, а не отдельный gaze-сэмпл, является основной единицей группового анализа.

### Групповые визуализации

- общая heatmap по выбранному stimulus;
- распределение метрики по участникам: boxplot или точки + медиана;
- таблица показателей по AOI;
- доля участников, зафиксировавшихся на каждой AOI;
- сравнение блоков, условий или заранее заданных групп;
- разница между выбранными группами/условиями с доверительным интервалом.

Статистические тесты и p-values стоит добавлять после согласования дизайна конкретного исследования: зависимые или независимые выборки, число условий, primary outcomes и правила множественных сравнений.

## 4. Фильтры

Одна панель фильтров используется для таблиц, графиков и export:

```text
Project → protocol/version → session/group → block → stimulus → AOI → QC
```

Дополнительно для групповой аналитики:

- группа/условие;
- период сбора;
- включение BORDERLINE-сессий;
- минимальная доля valid gaze.

В карточке сессии выбор конкретной session обязателен. В селекторе показываются код участника, дата, статус завершения и QC.

Export CSV/JSON должен выгружать точно ту же выборку, которая открыта на экране.

## 5. Как должен выглядеть шаг «Аналитика» в конструкторе

Исследователю не нужно показывать длинный список всех возможных статистик. На основном экране предлагаются компактные пакеты.

### Пакеты аналитики

#### 1. AOI и внимание — рекомендуется при наличии AOI

- heatmap;
- gaze-on-target;
- dwell time;
- fixation count/duration;
- TTFF;
- visits/revisits.

#### 2. Выполнение задачи

- accuracy;
- reaction time;
- errors;
- omissions/commissions.

Пакет доступен только для задач, в которых эти показатели можно вычислить.

#### 3. Групповая аналитика

- сводка выборки;
- распределения показателей;
- групповая heatmap;
- сравнение групп/условий.

#### 4. Качество данных — обязательно

- QC;
- valid samples/time;
- confidence;
- off-screen;
- версии алгоритмов.

Пакет нельзя отключить полностью, потому что без него результаты невозможно корректно интерпретировать.

### Предлагаемый вид страницы

```text
Что вы хотите анализировать?

[✓] AOI и внимание          Рекомендуется
[✓] Выполнение задачи       Доступно для выбранных задач
[✓] Групповая аналитика
[✓] Качество данных         Обязательно

Настроить отдельные показатели ▾

Разные настройки для отдельных задач ▾

Итог: AOI и внимание · Выполнение задачи · Группа · QC
```

В разделе «Настроить отдельные показатели» находятся сгруппированные чекбоксы, но он по умолчанию закрыт.

### Настройки по задачам/блокам

По умолчанию выбранный набор применяется ко всему эксперименту. При необходимости исследователь задаёт исключения:

```text
Общий набор: AOI и внимание + Выполнение задачи + Группа
Тренировка: только Выполнение задачи + QC
Основная часть: наследует общий набор
```

Настройки задаются на уровне блока/задачи, а не каждого trial. Конкретные session, stimulus и AOI выбираются позднее фильтрами в аналитике.

Важно: выбор на этом шаге определяет, какие результаты показывать по умолчанию, но не должен отключать сбор исходных gaze/QC данных. Тогда набор отчёта можно изменить после завершения исследования.

## 6. Приоритет реализации

### Обязательно до начала исследований

1. Удалить demo fallback из production analytics.
2. Связать AOI → protocol version → invitation → participant session → analytics.
3. Добавить выбор session и остальные фильтры.
4. Реализовать QC и различение zero / no data / low confidence / off-screen.
5. Реализовать heatmap и все AOI-метрики одной сессии.
6. Реализовать групповую сводку и описательные статистики.
7. Сделать единый фильтр для UI и export.
8. Добавить пакеты аналитики и настройки по блокам в конструктор.
9. Покрыть основной сценарий Playwright e2e.

### После запуска первой волны

- статистические тесты под конкретные дизайны исследований;
- анализ последовательности переходов между AOI;
- scanpath и entropy;
- корреляции между большим числом метрик;
- нормативы и percentiles;
- эмоциональные и физиологические показатели после отдельной валидации.

## 7. Что необходимо согласовать

1. Dwell time считать по фиксациям или по всем валидным gaze points?
2. Gaze-on-target считать от валидного времени взгляда или полного времени показа?
3. TTFF отсчитывать от начала stimulus или начала validity interval AOI?
4. Какой fixation algorithm и confidence threshold использовать?
5. Какие QC-пороги исключают session или trial?
6. Какие сравнения групп понадобятся в первых исследованиях?
7. Какие метрики будут основными outcomes, а какие дополнительными?

После согласования этих пунктов определения и версии алгоритмов должны быть зафиксированы до начала основного сбора данных.
